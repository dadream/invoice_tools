# Concur 式 UI 与原件预览重构需求

## 问题与目标

当前产品功能已具备，但批次审核采用三栏工作区，费用定位、原件查看和字段编辑同时挤在一页，造成严重信息过载；真实 Windows 候选中 PDF 与 OFD 原件均不能稳定显示。本轮目标是采用 Concur 值得借鉴的对象层级，建立“批次费用清单 → 单条费用全页详情”的清晰任务流，并将 PDF/OFD 应用内查看作为发布前 P0 能力。

## 范围

- 工作台、批次列表、新建批次、批次费用清单、导入、单条费用详情、重复处理、归组、完成审核、交付和设置页面。
- PDF/OFD/图片/XML 原件的应用内查看、错误恢复和外部打开。
- 自动保存、连续核对、页面上下文恢复、100%/125%/150% Windows 缩放布局。
- 更新相关自动化测试、发布缺陷记录和 Windows 免安装测试包。

## 非目标

- 不改变本地稳定 `ExpenseItem` 与 Concur 字段映射隔离原则。
- 不实现或伪造 Concur 最终提交、公司限额、审批和付款状态。
- 不修改用户真实批次数据，不启动 GUI 自动操作。

## 用户故事与验收标准

### R1 批次对象中心导航

- 当用户打开工作台时，系统应按批次真实处理状态显示下一步动作，而不是把所有草稿统一称为“审核中”。
- 当用户进入批次时，系统应仅提供“费用清单”和“归组”两个一级视图。
- 当用户创建批次时，系统应只要求批次名称，并由系统生成创建时间。

### R2 费用清单

- 当批次存在费用时，系统应以表格展示状态、实际日期、票据材料、费用分类、交易对方、地点、归组、实际金额和计入状态。
- 当用户选择状态筛选时，系统应能够分别定位阻断项、疑似重复、待挂载材料、待归组、已核对和已排除记录。
- 当用户点击费用行或“核对”时，系统应打开单条费用全页详情，并保留清单筛选与滚动上下文。

### R3 单条费用详情

- 当用户打开单条费用时，系统应最多显示左右两栏：左侧稳定费用表单，右侧原件查看器；任何窗口宽度都不得出现第三栏。
- 当可用宽度不足时，系统应将原件查看器切换为可打开的右侧抽屉/覆盖层，不得把定位队列、原件和表单同时堆叠。
- 当用户核对连续费用时，系统应持续显示当前/总数、上一条和下一条待处理。
- 当费用金额与票面价税合计不同，系统应显示差额警告；系统不得自动应用企业报销上限。
- 当用户离开当前费用时，系统应先保存修改；保存失败时应保留输入并阻止切换。

### R4 渐进披露

- 当费用无对应问题时，系统应默认只展开稳定费用字段，并折叠票据事实、材料、识别依据和历史。
- 当费用命中疑似重复时，系统应显示专用决策区和两条记录对比入口；疑似重复默认不计入总额。
- 当材料未挂载时，系统应在费用清单的专用队列处理，不得常驻挤占每张费用详情。

### R5 归组

- 当用户进入归组视图时，系统应以两栏显示归组列表和当前组详情，并单独展示待归组费用。
- 当用户重新分析归组时，系统应先确认影响，完成后要求重新核对并提供审计/撤销记录。
- 当不存在铁路、航空或行程单锚点时，系统不得自动建立差旅行程，并应解释缺失证据。

### R6 完成审核与交付

- 当用户准备完成审核时，系统应一次显示全部阻断项、警告、默认排除和计入总额，并为每个阻断项提供处理入口。
- 当阻断项清零并由用户确认时，系统应冻结审核版本，再进入独立交付选择。
- 当 Concur 适配器不可用时，系统应在交付入口直接显示不可用原因，不得让用户完成长流程后才发现不能上传。

### R7 PDF/OFD 原件查看

- 当原件为 PDF 时，系统应在应用内显示分页预览，并提供页码、上一页/下一页、缩放、适宽、旋转、重载和外部打开。
- 当原件为 OFD 时，系统应在应用内显示被动、安全的分页版式预览；原始 OFD 必须保持不变。
- 当首选渲染失败时，系统应显示具体恢复动作，包括重试、系统打开、打开所在文件夹和重新关联。
- 当用户在费用间快速切换时，过期渲染结果不得覆盖当前费用，也不得产生持续闪烁。

### R8 质量与发布

- 当运行前端检查、单元测试和生产构建时，系统应零错误通过。
- 当运行 Rust 目标测试、工作区测试和 Windows 验证脚本时，系统应零失败通过。
- 当构建免安装包时，产物应通过结构、隐私、依赖、磁盘和哈希门禁。
- GUI 人工验收由产品负责人使用最终测试包执行，自动化不得代替该验收。
