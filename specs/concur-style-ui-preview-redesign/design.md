# 技术与交互设计

## 设计基线

- 平台：Windows Tauri/WebView2，Svelte 5 + TypeScript。
- 方向：工业/专业财务工作台，浅灰工作面、白色内容面、松针绿主操作、琥珀待确认、红色错误。
- 字体：Source Han Sans SC；数字与编号使用 IBM Plex Sans/Mono。
- 结构：对象中心的列表到详情；单条费用固定为两栏或单栏 + 查看器覆盖层，废止三栏。

## 页面状态

`BatchList` 仍负责应用内批次路由，但保存批次、屏幕、筛选和选中费用上下文。`BatchDetail` 只组织费用清单、归组和底部审核完成状态；`ExpenseReviewPage` 作为独立全页详情，由费用清单进入。导入、完成检查、重复对比使用受控抽屉/对话框，不再常驻占用页面。

## 前端模块

- `BatchList.svelte`：工作台和批次状态/下一步。
- `BatchDetail.svelte`：紧凑页头、两视图、审核准备度。
- `ReviewWorkspace.svelte`：仅费用清单和筛选，不再包含三栏详情。
- `ExpenseReviewPage.svelte`：连续核对、稳定费用字段、票据事实折叠、重复决策、材料和原件双栏。
- `OriginalPreview.svelte`：统一图片/PDF/OFD/XML查看器和恢复状态。
- `GroupingSummary.svelte`：归组列表 + 当前组详情两栏。
- `ReviewReadinessDialog.svelte`：全部阻断项与定位动作。
- `BatchImportPanel.svelte`：来源、配置、预检、进度、结果分步。

## 预览后端

### PDF

保留现有 Windows PDF 页面渲染作为主实现，但修复 IPC 二进制返回、过期请求和错误分类；渲染结果以 PNG 字节返回前端。所有命令均验证文件路径、扩展名、大小和页码。

### OFD

OFD 不交给 WebView 执行。后端解析 OFD ZIP 中每页 `Content.xml` 的文本对象与毫米坐标，生成只读 `OFDPreviewPage` DTO；前端在 `<canvas>` 上以本地字体绘制分页版式。首版覆盖文本、基本页面尺寸和发票核心内容；原始文件保持不变，并始终提供系统外部打开。该方案避免执行 OFD 中的脚本/主动内容，也不把预览副本用于上传。

### 请求一致性

查看器为每次加载分配序号；只有当前费用、当前材料、当前页和当前序号完全一致时才接受渲染结果。组件销毁或切换记录时撤销旧 Object URL。

## 保存与导航

费用详情使用显式保存状态机：`saved | dirty | saving | failed`。所有切换费用、返回清单、切换折叠区和离开详情动作调用同一个 `saveBeforeNavigate`；失败时保持当前页和输入。`Ctrl+S` 保存，`Ctrl+Enter` 保存并进入下一条待处理。

## 响应式

- 可用宽度 ≥ 1040px：费用表单 56%，查看器 44%。
- 可用宽度 < 1040px：费用表单单栏，查看器作为右侧覆盖层；顶部按钮始终可达。
- 费用清单在窄宽度切换为可读卡行；不允许核心按钮因横向滚动不可达。

## 测试策略

- Svelte：列表/详情切换、保存失败阻止导航、金额差异、重复默认排除、查看器状态和无三栏断言。
- Rust：OFD页解析、恶意/损坏ZIP、页面边界、PDF页渲染错误分类和路径安全。
- 集成：审核准备度、冻结快照、Excel/Concur隔离、预览元数据。
- Windows：统一验证、免安装包结构、中文空格路径、真实批次人工PDF/OFD逐项查看。

## 风险

- OFD首版文本版式预览不能完整复刻所有矢量线框、印章和图片，因此查看器必须标识“应用内版式预览”，并保留系统打开原件；后续可在许可审核后替换为固定OFD渲染引擎。
- Windows PDF渲染依赖系统组件，自动测试通过不代表所有真实文件可用；真实批次人工验收是发布门禁。
