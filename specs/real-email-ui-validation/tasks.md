## 里程碑 M0：只读与秘密安全门禁

- [ ] 0.1 将 IMAP 文件夹打开从 `SELECT` 改为 `EXAMINE`
  - 为 QQ/163 的 ID 命令顺序补测试。
  - 验证只读打开后 SEARCH/FETCH 正常。
  - _需求：R2_

- [ ] 0.2 将正文抓取从 `BODY[]` 改为 `BODY.PEEK[]`
  - 补协议命令断言。
  - 补 FLAGS 前后不变测试。
  - _需求：R2_

- [ ] 0.3 建立 `ReadOnlyMailbox` 接口
  - 生产采集代码不暴露写邮箱方法。
  - 静态检查禁止 STORE/COPY/MOVE/APPEND/DELETE/EXPUNGE。
  - _需求：R2_

- [ ] 0.4 实现邮箱只读快照
  - 比较 UIDVALIDITY、UID、FLAGS、大小和 Message-ID 摘要。
  - 快照只覆盖 2026 年 6 月范围。
  - _需求：R2、R3_

- [ ] 0.5 建立安全测试启动器
  - 只加载 `.env.local` 允许变量，不打印任何秘密派生信息。
  - 固定测试邮箱、日期范围和北京配置。
  - 创建唯一 `INVOICE_ASSISTANT_HOME`。
  - _需求：R1、R4_

- [ ] 0.6 清理危险开发示例
  - 移除或改造硬编码 Linux `.env.local` 路径的 example。
  - 禁止真实附件写入仓库 `fixtures/`。
  - _需求：R1、R4_

### M0 门禁

## 建议迭代节奏

| 周期 | 目标 | 可交付结果 |
|---|---|---|
| 迭代 1 | M0–M1 | 邮箱严格只读、会话凭据、秘密安全 |
| 迭代 2 | M2–M3 | 流水线可靠、真实后端采集可重复 |
| 迭代 3 | M4 | 北京配置真实生效、人工审核闭环 |
| 迭代 4 | M5–M6 | 完整输出、Windows UI 自动化 |
| 迭代 5 | M7 | 签名免安装候选包、数据迁移/回退和 IT 审核材料 |
| 发布候选 | M8 | 从免安装 ZIP 执行两轮真实回归和脱敏发布报告 |

单人开发粗估为 4–7 周，取决于真实数据暴露出的解析、OCR、归组和输出缺口。每个迭代都必须保持普通合成测试可独立运行，不能让真实邮箱成为日常开发依赖。
