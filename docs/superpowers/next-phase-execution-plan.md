## Plan 2: MVP开发（优先级★★★★）

### 目标

**交付物：** 本地优先的发票管理桌面应用  
**时间：** 4周MVP上线  
**核心价值：** 用户可以本地解析发票，一键上传Concur

### MVP功能清单

**必须包含：**
1. 拖拽上传发票（PDF/XML，OFD待Plan 1.5）
2. 自动解析提取字段
3. 字段展示和手动编辑
4. 本地SQLite存储
5. 历史记录查询
6. 一键上传Concur（联网）
7. 发票验签（联网，可选）

**延后v0.5：**
- OFD支持
- 批量邮件导入
- 云端数据同步

### 技术栈

- **桌面框架：** Tauri (Rust + React)
- **数据库：** SQLite
- **解析器：** 复用Plan 1代码
- **OCR：** Python PaddleOCR sidecar
- **云端API：** 验签API + Concur Expense API

### 4周时间线

**Week 1: 基础框架**
- Tauri项目搭建
- SQLite数据层
- 集成spike解析器

**Week 2: 核心功能**
- 文件上传和解析
- 字段展示和编辑
- 本地存储

**Week 3: 云端集成**
- Concur OAuth + 上传
- 验签API对接

**Week 4: 测试发布**
- 集成测试
- 打包（Windows/macOS）
- 部署文档

### 本地/云端边界

**本地运行（离线可用）：**
- ✅ 文件解析（XML/PDF）
- ✅ OCR识别（Python sidecar）
- ✅ 数据存储和查询
- ✅ 字段编辑

**云端服务（联网必需）：**
- ⚠️ 发票验签（¥0.30/次）
- ⚠️ Concur上传

**优势：**
- 隐私保护（数据不上云）
- 零延迟（本地处理）
- 成本可控（月成本<¥50）

## 风险管理

### 关键风险

**Risk 1: Plan 1.5无法达到90%**
- **概率：** 中
- **影响：** MVP数据质量不足
- **缓解：** 
  - Week 1立即验证OFD渲染
  - 如果85-90%，接受为MVP基线
  - 低于85%，延长Plan 1.5

**Risk 2: Tauri技术栈不成熟**
- **概率：** 低
- **影响：** Plan 2延期
- **缓解：**
  - Week 1技术验证（Hello World + spike集成）
  - 如果有问题，切换Electron

**Risk 3: Concur API变更或限制**
- **概率：** 低
- **影响：** 核心功能受阻
- **缓解：**
  - Week 3前完成API文档研读
  - 设计适配层，降低耦合

**Risk 4: Python环境部署复杂**
- **概率：** 高（用户环境多样）
- **影响：** OCR不可用
- **缓解：**
  - 提供一键安装脚本
  - 文档详细说明
  - v0.5考虑内置Python或云端OCR备选
