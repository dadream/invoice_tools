# 缺陷分级与发布门禁

> 适用范围：Windows MVP 开发、系统验证、Alpha、Beta 和正式发布

## 1. 缺陷等级

| 等级 | 定义 | 示例 | 发布处理 |
|---|---|---|---|
| P0 | 数据、安全或不可逆严重事故 | 授权码泄露、邮箱状态改变、误删用户目录、数据损坏、重复真实外发 | 立即停止；0 个方可继续 |
| P1 | 核心流程不可完成或结果不可信 | 无法采集/审核/输出、金额错误、恢复失败、签名无效 | 原则上 0；Alpha 仅可书面限时豁免非安全项 |
| P2 | 有明确规避方式的主要问题 | 单一格式失败、缩放下次要操作不便 | 可带负责人、目标版本和规避说明进入阶段 |
| P3 | 不影响任务完成的体验或文案问题 | 间距、非关键提示不一致 | 记录并排期 |

## 2. 缺陷记录字段

每项至少记录：ID、标题、版本/提交、环境、等级、复现步骤、预期、实际、影响、脱敏证据路径、负责人、目标阶段、回归用例和状态。不得附真实授权码、邮件正文、完整票号、税号或原始发票截图。

## 3. 豁免

- P0 不得豁免。
- 邮箱状态变化、数据损坏、秘密泄露、误删和重复外发不得豁免。
- P1 仅内部 Alpha 可由产品负责人书面批准，必须写明影响、规避、截止日期和撤销条件。
- Beta 与正式版 P0/P1 必须为 0。

## 4. Go/No-Go 报告

报告必须绑定一个不可变提交和一个候选包哈希，包含：

1. 阶段与候选版本。
2. Windows/工具链/缩放/路径环境。
3. 自动化、真实 UI、邮箱、恢复、安全和打包结果。
4. P0–P3 数量与未关闭清单。
5. 签名、时间戳、SHA-256、SBOM 和许可结果。
6. 外部真实操作的批准记录。
7. 结论：Go、No-Go 或仅限内部使用。

## 5. 阶段门禁

- 系统验证：M0–M9 功能和包完成，同一提交自动回归通过。
- Alpha：P0=0，未签名包必须在文件名、README 和 About 明示。
- Beta：P0/P1=0，签名/时间戳/支持信息/QQ+163/Concur 门禁完成。
- 正式版：最终签名产物重跑关键回归，下载页和回退演练通过。
