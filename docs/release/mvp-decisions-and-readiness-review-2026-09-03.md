> 产品确认：除真实 Concur 草稿导入/上传闭环外，MVP 其他功能均已实际验证

## 1. 结论

当前代码可作为 **Windows x64 免安装、未签名、授权内部 Alpha** 的候选基础。非 Concur 功能已经产品负责人实际验收，本次审查未发现需要推翻现有本地流程的规格冲突。

当前不能把完整 Concur 核心闭环标记为已完成：代码只实现了本地企业映射、必填缺口预检、冻结投影、幂等上传会话和明确的外部写入禁用态；尚未在指定 Concur 租户完成未提交报销单创建、费用填写、发票/配套材料关联、回读核对、未知状态恢复和防重复验证。这是功能 MVP 唯一未完成的真实集成验证。

“非 Concur 功能已验收”不等于“可公开发布”。公开 Beta/正式版仍受历史票据夹具隐私处置、可信代码签名/时间戳、正式发布主体与支持渠道、可信下载地址、163 邮箱承诺、外部 Beta 和最终签名 RC 等门禁约束。

| 结论对象 | 状态 | 是否可对外宣称 |
|---|---|---|
| 本地采集、导入、解析、费用核对、去重、归组、材料、Excel、打印 PDF | 产品验收完成 | 可在授权内部 Alpha 范围说明 |

| Concur 映射配置、预检、禁用态 | 已实现并自动验证 | 可说明“准备能力”，不可说已上传 |

## 2. MVP 全部决策索引

完整决策原文、替代关系和确认日期在 `specs/mvp-release-baseline/decision-record.md`。以下为执行摘要。

### 2.1 产品、账户和数据边界

- Windows 11 x64 本地桌面版；首发为解压即用 portable ZIP，程序与 DataRoot 分离。
- MVP 无产品账号、登录、订阅、计费、云同步、应用层数据库加密和跨设备同用户认证。
- 数据属于用户；MVP 用显式未加密备份包满足跨电脑迁移，并提供完整性校验和隐私警告。账号绑定用户级密钥、加密备份和密钥恢复在功能发布稳定后建设。
- 邮箱授权码只在当前进程内存中存在，不写数据库、配置、日志、备份或发布包。
- 无外部大模型、云 OCR、匿名遥测和后台自动更新；联网只由用户明确触发。

### 2.2 输入和邮件收集

- 邮件收集是独立任务，只负责只读检索、分类、附件下载、正文链接/二维码提取、文件完整性和用户审核，不解析发票。
- 收集结果永久复用；进入详情不重访邮箱，只有“重新分析该邮件”才更新缓存。
- 邮件列表按收件日期显示待审核、已审核、需要用户处理三组；单封页展示主题、发件人、日期、安全纯文本正文、附件、链接和二维码。
- 同一邮件附件保持来源关联；支持无效附件、用户补充、完成后跳到当前队列下一封和删除收集任务。所有远端邮件状态保持不变。
- 新建批次只填写名称，创建时间由系统记录；进入批次后才选择邮件收集结果或本地票据文件。
- 本地导入对象是发票、行程单、明细、水单等票据文件/文件夹，不提供 EML 用户入口。

### 2.3 发票单、费用和材料

- 主发票、行程单、消费明细、其他材料和重复来源副本挂在一个发票单上；配套材料不独立计费。
- 单条核对使用稳定 `ExpenseItem`；发票号、票面日期、税号等事实留在 `InvoiceRecord`。Concur 字段只存在于目标映射和上传会话。
- 费用清单主要确认实际日期、费用类型、实际金额和交易方；归组只确认组成员关系。两者分别保存，不互相阻断。
- 批次内容以本次费用、未计入、待处理材料管理。未计入不新建数据结构、不强制原因；材料可挂载、转费用或明确忽略。滴滴行程单可人工转费用。
- 疑似/确认重复默认不计入总额和交付，只有用户明确确认“不是重复”才恢复计入；底层原件不删除。

### 2.4 分类、归组和验签

- 自动分类覆盖城际交通、住宿、餐饮、市内交通（含滴滴）、快递/物流；铁路方便食品归餐饮。
- 零食、健身、服装不增加 MVP 专用分类，证据不足保持未分类。
- 行程单和城际交通的日期/路线是主要归组依据；支持可编辑常驻城市站点别名、退票与替代购票、公司购买交通时的住宿独立出差、市内交通/餐饮按地点日期归入及快递物流独立组。
- 归组名称是稳定可点击业务名称；组内默认按类型、同类型按日期，也可按日期。系统无法确定时必须允许人工覆盖。
- MVP 不做发票密码学验签，不把“验签不支持”变成逐条任务或审核阻断。

### 2.5 页面和交付

- 批次只有费用清单和归组两个一级视图；完成审核前不出现导出和上传主操作。
- 列表进入独立详情；单条费用使用左侧稳定字段、右侧原件查看器，避免三栏信息过载。PDF/OFD/图片需要稳定预览，至少支持折叠、恢复、全屏和 PDF 连续滚动。
- 完成审核冻结 `ReviewSnapshot`，再进入独立交付选择。交付页以“导出文件”和“上传到 Concur”为主入口。
- Excel 使用稳定本地费用字段。打印 PDF 只含计入费用的有效发票/材料，第一页即凭证，无封面、目录和异常附录；所有页面使用全局页码，生成过程显示进度，失败材料只在 UI 告知。
- Concur 必须创建未提交报销单草稿、创建/填写费用并关联正确原件，使用实际票面金额。公司限额、核准金额、审批和最终提交由用户在 Concur 处理。

## 5. Concur 验证完成定义

在任何真实写入前，产品负责人需提供指定测试租户、允许的官方 API/集成或可见 UI 辅助方式、测试用户、字段/选项稳定 ID、附件语义和当次写入批准。验证必须使用脱敏测试批次并完成：

1. 登录/SSO/MFA 由用户可见地完成，不持久化密码或可复用 Cookie；
2. 创建且只创建一个未提交报销单草稿；
3. 只为计入费用创建条目，实际金额、日期、类型、地点等字段与冻结投影一致；
4. 每笔费用关联正确主发票和配套材料，漏传/错关联为零；
5. 回读报销单、费用和附件 ID，与本地映射快照逐项对账；
6. 在断网/中断/超时产生未知状态时先查询再决定，不盲目重建；
7. 重复点击和恢复不得生成重复报销单、费用或附件；
8. 软件停在未提交状态，由用户在 Concur 处理公司规则并最终提交。
