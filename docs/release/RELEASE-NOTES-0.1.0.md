# 0.1.0 内部 Alpha 发布说明

> 2026-08-25 产品范围说明：用户可见的本地导入只支持发票及配套票据文件/文件夹，不把 `.eml` 作为选择器、拖放区或帮助文案中的正式输入。本文中的 EML 只表示邮箱采集内部解析、合成夹具或早期候选验证路径，不构成产品入口承诺。

## 本轮能力

- Windows 11 x64 免安装 Release EXE，程序与数据目录分离，不申请管理员权限。
- XML、OFD、文本 PDF、扫描 PDF、PNG/JPG/JPEG/WebP/BMP 发票/配套票据文件及包含这些文件的本地文件夹输入；邮箱模式使用仅驻留当前进程内存的会话授权码。
- 生产 XML 标签并集覆盖现有真实平台标签与合成端到端夹具的 `IssueDate/TotalAmount/TaxAmount`；仓库合成 EML 仅用于验证邮箱采集内部收集和解析路径。
- 铁路电子客票 PDF 优先读取受限 `EmbeddedFiles` XBRL/XML，再降级到文本与 OCR；重复载荷去重，关键字段冲突拒绝自动选择，附件数与压缩/解压大小均有硬上限。
- 图片与扫描 PDF 使用随包交付的离线 OCR 模型和 ONNX Runtime，不依赖 Python、网络或安装程序；L2 OCR 与低置信结果强制进入人工复核。
- OCR 在独立 `invoice-ocr-worker.exe` 中执行：最大并发 1、单文件 45 秒硬超时，崩溃/超时不拖死主 UI；Release 启动前按 portable manifest 校验 worker SHA-256；两个 EXE 的静态 DLL 依赖限定为 System32，运行期只登记已校验 OCR 目录，并忽略工作目录、PATH/ORT_DYLIB_PATH 中的诱饵 DLL。
- IMAP 只读 `EXAMINE`/`BODY.PEEK`、命令白名单与读取前后 FLAGS 指纹。
- 对仅通过邮件正文链接交付的发票生成安全提示：产品只保存“疑似链接交付”数量，不保存或自动访问正文 URL；用户在邮箱客户端核对发件人和域名、手动下载后，可从“本地文件”继续导入。
- 流水线按收集、解析、去重、归组写入校验检查点；解析结果使用 `formatVersion=1` 与 `parserVersion` 包络，恢复时拒绝不兼容格式；启动时识别中断任务并允许恢复，最终批次事务幂等。
- 运行中支持“安全停止”：等待当前文件结束、保留最近检查点并回到可恢复任务；邮箱路径仍先完成只读 FLAGS 核对。
- 本地票据与邮箱内部展开共用资源预算：单文件 25 MiB、最多 5000 个文件、总暂存量 500 MiB，并拒绝目录重解析点。
- 本地解析和确定性归组；规则版本、置信度、歧义、成员和匹配依据进入账本与审核页。
- 草稿审核使用分组/原件/字段三栏工作区，支持字段编辑、重复项确认、人工新建/移动/合并归组、归组确认、操作历史、顺序撤销和发票剔除/恢复。
- 创建批次弹窗支持初始焦点、焦点循环、Esc 关闭和焦点返回；本地来源为空时会显示可访问的明确错误提示。上述交互已在更早候选的 Windows 11 标准用户、150% 缩放 packaged EXE 上完成点击与键盘回归；当前主程序另通过合成 EML 技术路径验证内部邮件展开，并完成全新隔离首次设置、无效数据根和链接型完成页安全提示走查，但仍需移除用户可见 EML 入口并完成 packaged UI/故障矩阵。
- 税务/开票 App 的“开票成功/扫码下载”结果页即使显示号码、日期和金额，也不会作为发票原件进入草稿；规则同时要求状态与操作锚点，避免单个“成功”词误伤真实发票。
- 对可读文本明确同时包含“行程单”和已知网约车平台、且不含发票/税务锚点的辅助材料，在结构化与文本解析均失败后直接进入人工核对，不再消耗 OCR；规则不会泛化到其他文本 PDF。
- 疑似/确认重复默认不参与统计、最终输出或Concur费用创建，未决定时继续保持“本次不上传”，不阻断其他已确认费用；只有用户明确选择“不是重复，计入总额”才恢复计入。签章失败、金额不一致等真正阻断项及必须确认的归组问题未解决时不能输出或上传；草稿和驳回批次不能生成最终输出。
- 推荐输出包使用稳定任务键、逐文件 SHA-256、局部恢复和原子发布，包含 Excel、CSV、PDF 台账、A4 规范化合订本及原件 ZIP。
- 原件 ZIP 保存原始字节与独立 SHA-256 索引，不写入本机源文件路径；审核页通过发票 ID 安全预览 PDF、常见图片和 XML。
- 数据/程序清除预览、确认短语和 portable manifest 约束的临时清理器。
- WebView2、目录可写性、同步/网络目录、磁盘空间和数据库启动前检查；旧 schema 打开前创建经版本/完整性校验的迁移快照，全部迁移位于单一事务，故障注入证明失败后原库逐字节不变；未来 schema 在零修改前提下拒绝打开。
- 用户触发的版本检查只读取固定 HTTPS JSON，验证产品、渠道、语义版本、说明、ZIP SHA-256 和下载页；不自动检查、下载、替换或提权。当前内部 Alpha 未配置正式 URL，因此不会联网。
- Concur 收据邮件已实现本地计划、试发、租户行为确认、批量发送状态、成功防重、失败局部重试和 unknown 人工核对；只接受已审核的 PDF/图片附件。内部 Alpha 构建硬性关闭真实 SMTP，只展示和校验本地计划。
- 未加密备份、逐文件 SHA-256/SQLite 校验和重启前原子导入；ledger schema 与备份 manifest 使用同一版本常量；授权码、日志和本机邮箱配置被排除。
- 解析失败日志只记录候选序号、扩展名和静态失败分类，不记录第三方错误字符串、本机路径或原件文件名；专项单测锁定该约束。

## 阻断性已知限制

- 历史 `fixtures/test-images` 不能证明为合成数据；当前工作树已隔离并以合成夹具替换，但 Git 历史及可能的远端克隆、缓存和旧制品尚未受控清理。该 P0 关闭前不得公开发布。
- 图片和扫描 PDF 的离线 OCR 已通过非隐私合成 golden；本批真实 QQ 最终接受 84/84 个有效发票（PDF 54/54、OFD 21/21、XML 8/8、PNG 1/1），9/9 个无效或非发票被拒绝，已覆盖槽位与产品输出 84/84 一致。该结果仅是本批 110 个去重附件的文件级证据。在最终 105 个产品候选集上，稳定排序前 50 个累计解析 30.285 秒，39/39 有效发票成功、11/11 非有效候选拒绝；完整 105 个累计 94.427 秒，84/84 有效发票成功、21/21 非有效候选拒绝，成功结果 JSON 相对最终基线无变化。参考机 5 分钟性能门禁已通过，但其余 168 个核心字段槽位、峰值内存、最低配置和第二台物理机证据仍未完成；可选税率字段仍可能误识别，OFD 暂未接入栅格化 OCR。所有 OCR 结果必须人工复核。
- 三栏审核、剔除/恢复和键盘快捷路径已实现并通过编译/回归；更早候选在 Windows 11 标准用户、150% 缩放下完成首次设置、导航、设置及定向弹窗键盘走查。当前候选仍缺完整 packaged UI，发布矩阵另缺 100%/125%、完整审核/导出/备份 UI 和第二台物理机。OFD 暂不提供可视化预览。UI 已内置 Source Han Sans CN 与 IBM Plex Sans/Mono，A4 PDF 内置 Source Han Sans CN TrueType，不依赖系统字体；OFL 文本随包交付。
