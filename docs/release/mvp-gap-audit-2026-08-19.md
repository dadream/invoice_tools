# Windows MVP 发布缺口基线审计

> 状态：实施中，内部 Alpha 候选可生成，公开发布仍阻断
> 审计更新：2026-08-23
> 规格基线：`specs/mvp-release-baseline/` 1.0（已确认）

## 1. 当前结论

当前仓库已具备 Windows x64 免安装内部 Alpha 的代码与自动化基线，但尚不能作为公开 Beta 或正式产品发布。全量 Rust 测试已通过 483 项、UI 测试通过 14 项；图片和扫描 PDF 的离线 OCR 已完成集成并通过非隐私合成 golden。真实 QQ 只读和本批文件级解析已完成，但完整字段黄金真值、真实混合批次性能、真实 UI/缩放、签名和外部 UAT 仍是发布证据缺口。

## 2026-08-20 实施更新

本轮关闭或显著收敛的初始缺口：

- 流水线任务和阶段进入 ledger schema v6，收集/解析/去重/归组检查点带哈希校验，异常启动后可列出并恢复；最终批次写入原子且幂等。
- ledger 初始化/连续迁移已合并为单一事务；v5→v6 故障注入证明原库文件逐字节不变。旧 schema 启动前创建并校验独立迁移快照，成功后保留供人工回退，当前/未来 schema 不误生成快照。解析检查点保存格式/解析器版本并拒绝未来格式；归组、备份、输出版本总审计和 portable 快照回滚/再次迁移闭环通过。
- Windows DLL 搜索已专项加固：两个自有 PE 的静态导入限定 System32，运行期排除工作目录、PATH 和未验证应用目录，只登记哈希通过的 OCR 目录；诱饵 DLL 对抗测试通过。
- 本地文件、递归文件夹、EML 和邮箱附件统一进入稳定原件目录；同名不同内容不会覆盖，未知或篡改文件被拒绝。
- 审核闭环支持字段编辑、确认非重复、人工新建/移动/合并归组、归组确认、操作历史、顺序撤销和发票剔除/恢复；非草稿批次拒绝修改。
- 提交门禁同时检查疑似重复、签章无效、归组歧义和 `requires_review`。
- 审核 UI 已统一为 224 px 导航与分组/原件/字段三栏工作区，接入异常提示、字段编辑、移动/合并、确认、撤销、剔除/恢复及键盘快捷路径；Svelte/TypeScript 为 0 错误、0 警告。
- 推荐输出包实现稳定任务键、局部恢复、逐文件 SHA-256、manifest 和原子发布，生成 Excel、CSV、PDF 台账、A4 规范化合订本及原件 ZIP。
- 原件 ZIP 保存精确字节和 SHA-256 索引，不包含源文件绝对路径；原件内容变化会改变任务键。
- 备份导入、受控清除、WebView2/目录/磁盘/数据库启动检查、秘密扫描、SBOM 和 portable 构建链保持通过。
- Concur 邮件的 schema v6 状态、试发确认、批量幂等、失败/未知分流、模拟 SMTP、UI 和内部 Alpha 关闭门禁已实现；真实外发仍等待指定租户、收件地址和逐次批准。
- 图片（PNG/JPG/JPEG/WebP/BMP）和扫描 PDF 已接入本地离线 OCR；模型及 ONNX Runtime 随 portable 包交付，不依赖 Python、网络或安装程序。L2 OCR/低置信结果一律进入人工复核。
- OCR 已隔离到单并发 worker，每文件 45 秒硬超时；参考机器生产 worker 的 50 张合成估算约 179.7/212.3 秒，峰值约 377–508 MiB。仍需真实混合批次和最低配置物理机验证。
- 统一 Windows 门禁当前通过：Rust 483 项、UI 14 项、0 失败。默认测试中 14 项显式忽略，其中图片引擎、扫描 PDF 引擎和生产 worker 端到端 3 项 OCR 合成/进程 golden 由发布门禁单独强制执行并通过；授权的真实 QQ 私有解析已另行执行，其余外部/私有验证不得由忽略状态替代。

当前仍阻断公开发布的事项：

1. 图片与扫描 PDF 的离线 OCR、资产哈希、资源上限、worker 硬超时、合成 golden 和参考机性能已完成；本批真实有效发票文件级解析 84/84，但仍缺其余 168 个核心字段槽位的人工黄金真值、真实混合批次与最低配置性能，OFD 栅格化 OCR 尚未完成。
2. 三栏原件预览、剔除/恢复和键盘快捷路径已实现，但真实 Windows 点击/完整键盘走查/缩放矩阵仍未取得证据；OFD 可视化仍未完成。
3. 操作系统子进程强杀/ledger 重开已自动验证，但 packaged GUI 强杀仍缺人工证据；A4 合订本仍缺打印预览和跨格式逐字段对账。
4. 用户触发的安全版本检查已实现；正式 HTTPS 清单/下载页仍待发布负责人配置。Concur 代码/UI/模拟验证已完成但内部 Alpha 强制关闭，受控真实试发和 163 正式支持等待阶段资源。
5. 跨数据根备份往返与真实 QQ 只读已自动验证；真实 Windows 点击/干净机/异常环境矩阵和两台物理电脑往返导入尚未完成。
6. Authenticode 签名、时间戳、正式法律/支持/下载元数据、外部 UAT 和最终 Go/No-Go 仍由产品负责人按阶段提供。

## 3. 发布阻断项

### P0/P1 工程阻断

1. 审核阶段当前仍是“自动通过”占位实现。
2. 归组结果计算后未进入台账和审核模型。
3. 流水线仅支持邮箱，无法完成产品定义的文件夹和 EML 本地模式。
4. 任务状态仅依赖内存事件，应用被强杀后无法恢复。
5. 备份/导入、清除程序、portable ZIP、WebView2 原生检查未实现。
6. Concur 发送未实现，且在产品负责人逐次批准前不得真实外发。

### 外部发布阻断

- 对外 Beta/正式版需要签名证书主体、发布主体、软件许可证、版权人、正式支持/隐私/安全邮箱、隐私政策与协议网址、可信下载地址和 Go/No-Go 批准人。
- 公开支持 163 邮箱前需要受控测试账号。
- Concur 验证需要指定测试租户、收据邮箱和逐次真实发送批准。

## 4. 下一实施顺序

1. 完成 M0/M1 治理、工具链和自动门禁。
2. 完成 M2 启动检查、数据版本与可恢复状态。
3. 完成 M3 本地来源、只读协议防线和会话凭据验证。
4. 完成 M4/M5 多格式路由、校验、归组入库和人工审核门禁。
5. 完成 M6–M9 UI、输出、备份、清除和 portable 发布。
6. 在秘密扫描和只读指纹防线通过后才执行 M10.3 真实 QQ 验证。
7. Alpha、Beta 和正式版按用户资源、真实用户验收和签名条件逐阶段推进。
