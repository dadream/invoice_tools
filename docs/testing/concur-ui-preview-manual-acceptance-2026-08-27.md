## 验收前提

1. 可保留旧版本运行，但不得同时编辑同一个数据目录中的同一批次。
2. 如 Windows 显示未知发布者提示，应先核对上述 ZIP 哈希，再按内部测试流程运行。
3. 不需要安装；不要把程序放在同步盘、网络盘或受控程序目录。

## A. 批次与导入

1. 打开批次列表，确认首页显示“草稿批次”“已完成审核”和批次金额概览，不再把静态四步流程误标为当前进度。
2. 新建批次，确认表单只有“批次名称”；创建时间由系统生成，不出现日期范围、邮箱来源等字段。
3. 进入批次后点击“导入数据”，确认导入在右侧抽屉中完成：
   - 邮箱导入：选择开始/结束日期后只读获取；
   - 本地导入：只接受 PDF、OFD、XML、图片和文件夹，不接受 EML。

## B. 费用清单

1. 打开真实批次 `test`（历史 id 4，如数据已迁移则按名称查找）。
2. 确认清单列为日期、费用与凭证、交易方/地点、归组、状态、实际金额；问题记录优先显示。
3. 分别测试搜索、状态、类型、归组筛选；打开一条费用并返回后，筛选条件应保留。
4. 检查重复记录：疑似重复和已确认重复都显示“未计入”；只有选择“不是重复”后才恢复计入总额。

## C. 单条费用核对

1. 从费用清单打开任一费用，确认进入完整页面，不再出现永久三栏布局。
2. 宽窗口下应为左侧费用表单、右侧原始凭证；窄窗口下凭证改为“查看原件”抽屉。
3. 主表单只显示本软件稳定字段，不显示 Concur 字段名；票面字段、重复判断、材料按需展开。
4. 修改费用字段和票面字段后点击“保存并到下一问题”，两组修改都必须保存，不能因刷新丢失。
5. 票面金额与实际报销金额不一致时显示差异提示，但批次始终按“实际报销金额”计算；软件不应用公司的餐费上限。
6. 使用上一条、下一条、保存并到下一问题连续核对；返回清单后仍位于原筛选上下文。

## D. PDF、OFD 与材料

1. 分别选择 PDF、OFD、图片和 XML 原件。
2. PDF：应显示分页图片；若 Windows PDF 光栅渲染失败，应自动显示兼容文本版式，而不是空白或持续闪烁。
3. OFD：应显示分页只读版式，可翻页、缩放和旋转；如原件只有复杂矢量轮廓，文本位置应仍可核对。
4. 缺失原件应显示明确错误与“重新关联原件”，不能闪烁；重新关联必须通过哈希或关键字段校验。
5. 配套材料从费用清单顶部进入独立抽屉，必须选择所属费用及“行程单/明细/其他材料”；材料本身不生成费用金额。

## E. 归组与完成审核

1. 切换“归组”视图，确认左侧为归组清单、右侧只显示当前归组详情。
2. 差旅行程应显示铁路、航空或已挂载行程单锚点；餐饮、酒店和市内交通需在明确行程组内归属。
3. 测试移动费用、合并归组、新建人工归组、重新分析和确认归组。
4. 点击“完成审核”时应始终打开完整检查单，逐项显示计入费用、日期、签章、材料、归组；有阻断项时不能继续冻结。

## F. 交付

1. 完成审核后才出现 Excel / Concur 两种交付选择，批次处理页不直接显示输出与上传。
2. Excel 使用冻结审核版本，可重复导出。
3. Concur 卡片应在进入前显示当前环境能力；进入后可配置公司映射、报销单名称/日期/备注、执行必填预检并查看费用及附件投影。
4. 本未签名内部 Alpha 包应明确显示外部写入未解锁，不能假装已经创建 Concur 草稿；最终提交始终由用户在 Concur 完成。

## 记录问题

记录页面、批次、费用 ID、原件格式、期望结果、实际结果和截图；不要在问题记录中包含邮箱授权码、完整税号或未经脱敏的发票内容。
