> 更新日期：2026-08-26
> 适用产品：Windows x64 免安装本地版发票报销助手

## 1. 文档目的

本文档从产品角度统一回答：

1. 用户从启动软件到把整理结果上传为 Concur 草稿的完整 UI/UX 流程是什么；
2. 批次、导入任务、发票单、稳定本地费用项、目标映射和输出之间是什么关系；
3. 当前软件已经具备什么能力；
4. 当前功能、交互和发布还缺什么；
5. 应按什么顺序优化，哪些是发布前 P0，哪些属于发布后增强；
6. 每项优化如何验收。

本文档作为产品优化的主索引。字段细节以《Concur 字段映射方案》为准；页面细节以《Concur UI 对标评审与优化方案》为准；发布事实仍以 `docs/release/open-defects.md` 和发布门禁证据为准。

## 2. 产品定位和边界

### 2.1 产品定位

本产品是个人用户侧、免安装、本地优先的发票报销预处理工具：

```text
邮箱或本地文件
→ 获取发票
→ 识别有效票据
→ 解析实际票面数据
→ 去重与归组
→ 用户核对
→ 完成审核并冻结本地结果
→ 选择交付：导出 Excel，或上传到 Concur
→ 上传路径创建报销单草稿、创建并填写费用、上传且关联发票
→ 用户进入 Concur 完成公司规则调整和最终提交
```

产品核心价值是把发票查找、下载、识别、整理、核对和 Concur 草稿录入连接成一个闭环。软件负责把用户确认后的真实票面数据和原始发票安全地写入 Concur 草稿，但不替代公司报销系统的政策判断、审批和最终提交。

### 2.2 产品负责

- 通过严格只读 IMAP 按用户指定日期范围获取邮件附件；
- 手工导入本地发票文件或包含发票文件的文件夹；`.eml` 不作为用户可见的本地导入对象；
- 识别有效发票、辅助材料、无效文件和损坏文件；
- 将主发票、行程单、消费明细和其他配套材料聚合到同一发票单；
- 解析发票号码、开票日期、价税合计等票面数据；
- 标记同批、跨批和历史重复，不自动删除证据；
- 根据常驻地、城市、日期和票种形成可解释归组；
- 提供原件对照、字段修正、排除、恢复和审计记录；
- 按发票实际价税合计准备申报金额；
- 生成本地输出；
- 在用户明确触发后创建 Concur 报销单草稿；
- 为每笔已确认费用创建 Concur 费用条目并填写可确定字段；
- 上传原始发票并与对应费用条目建立一对一关联；
- 对创建、填表、附件上传和关联结果逐项核对，支持失败重试和防重复；
- 在直接草稿上传不可用时，提供 Concur 收据邮件或本地导出作为兼容降级路径。

### 2.3 产品不负责

- 不执行企业餐费、住宿费、交通费等报销上限；
- 不把实际发票金额按公司规则从 126 元改成 80 元；
- 不判断企业最终可报金额、可抵扣税额、核准金额或付款金额；
- 不自动访问邮件正文中的未知下载链接；
- 不自动点击 Concur 最终提交；
- 不在用户不知情或不在场时操作 Concur；
- 不保存 Concur 密码、浏览器会话 Cookie 或其他可复用登录凭据；
- 不冒充 Concur 的审批、付款或核准状态；
- MVP 不要求账号、登录、云同步或应用级加密；
- 账号绑定、用户加密和跨电脑加密备份在核心功能发布后实施。

## 3. 产品核心对象

清晰的数据对象是 UI 流程成立的前提。

### 3.1 报销批次 `Batch`

批次是唯一核心工作对象。

创建时仅包含：

| 字段 | 来源 | 规则 |
|---|---|---|
| 批次名称 | 用户输入 | 唯一创建表单字段 |
| 创建时间 | 系统生成 | 本地时间，只读 |
| 批次 ID | 系统生成 | 内部稳定标识 |

批次创建时不填写：

- 月份；
- 日期范围；
- 邮箱；
- 发票来源；
- 授权码；
- 输出位置；
- Concur费用类型；
- 公司报销政策。

总金额、发票数、票据日期覆盖范围、问题数和状态由后续导入及审核动态计算。

### 3.2 导入任务 `ImportRun`

每次邮箱或本地导入都是批次内独立、可恢复、可审计的任务。

通用字段：

```text
import_run_id
batch_id
source_kind
started_at
finished_at
status
found_count
accepted_count
duplicate_count
rejected_count
failed_count
last_error
checkpoint
```

邮箱导入额外字段：

```text
email_account_id
search_date_start
search_date_end_exclusive
mailbox_folder
read_only_fingerprint_before
read_only_fingerprint_after
```

本地导入额外字段：

```text
selected_path_count
input_kind: invoice_file | invoice_folder
```

日期范围属于邮箱导入任务，不属于批次。本地导入器只接收发票及其配套票据文件；邮件消息的解析属于邮箱采集内部能力，不在UI中暴露 `.eml` 入口。

### 3.3 原始文件 `DocumentAsset`

代表不可修改的原始文件及其来源证据：

- 原始文件路径；
- 文件名、格式、大小、哈希；
- 来源导入任务；
- 邮件或本地来源的脱敏关联；
- 解析状态；
- 原件可预览状态；
- 文件角色：`invoice`、`itinerary`、`detail`、`other_supporting`、`duplicate_copy`、`invalid`；
- 所属发票单ID；无法确定归属时进入“待挂载材料”，不能独立计入费用。

### 3.4 发票单聚合 `InvoiceRecord`

发票单是票据聚合对象，也是稳定本地费用项的默认一对一来源。它包含一份主发票事实和零到多份配套文件：

```text
InvoiceRecord
├─ primary_invoice: DocumentAsset
├─ itinerary_documents: DocumentAsset[]
├─ detail_documents: DocumentAsset[]
├─ other_supporting_documents: DocumentAsset[]
└─ duplicate_source_copies: DocumentAsset[]
```

主发票事实包括：

- 发票号码；
- 开票日期；
- 价税合计；
- 税额、税率；
- 购方、销方；
- 票种、城市、出发时间、入住日期；
- 解析来源和确认状态；
- 重复关系；
- 金额计入状态和计入依据。

行程单和消费明细只作为主发票的证明材料或解析补充，不单独形成发票、费用或金额。无法自动挂载的材料进入待处理队列，由用户选择目标发票单。相同发票再次导入时保留来源副本，但一个 `InvoiceRecord` 只形成一笔默认费用、只计算一次金额。

金额计入状态固定为：

```text
included                         正常计入
suspected_duplicate_excluded     疑似重复，默认不计入
confirmed_duplicate_excluded     已确认重复，不计入
user_confirmed_distinct_included 用户确认不是重复，恢复计入
manually_excluded                用户排除，不计入
```

批次申报总额只汇总 `included` 和 `user_confirmed_distinct_included`。疑似重复一旦命中即从总额和Concur待上传费用数中排除；只有用户明确执行“不是重复，计入总额”后才恢复。

### 3.5 明确行程组 `TripGroup`

行程组必须先作为显式对象成立，不能先把所有发票模糊聚在一起再倒推行程。每个行程组至少包含：

- 稳定 `trip_group_id`；
- 明确起止日期和城市链；
- 至少一条行程锚点证据，如铁路/航空城际票据或已挂载的行程单；
- 形成依据和确认状态；
- 已归入及待确认归入的发票单列表。

处理顺序固定为：先从强行程证据建立候选组，再判断酒店、餐饮、出租车等其他发票单是否属于已经形成的组。证据不足的发票保持“待归组”，不得为了提高归组率强行塞入某个行程。没有城际/行程锚点时，不自动创建差旅行程；常驻地费用可以进入独立的“市内消费”集合，但不能冒充差旅行程。

### 3.6 稳定本地费用项 `ExpenseItem`

单条费用核对维护软件自己的稳定业务字段，不以Concur或任何目标报销系统命名：

- 软件内部费用分类 `category_code`；
- 实际发生日期 `transaction_date`；
- 费用说明 `description`；
- 交易对方 `counterparty_name`；
- 结构化发生地点 `location`；
- 付款方式 `payment_method`，允许未知；
- 实际金额 `gross_amount` 和币种 `currency_code`；
- 票面税项 `tax_details[]`；
- 关联行程、计入状态；
- 每个字段的来源、确认状态和人工修改记录。

发票号、开票日期、购销方税号和解析证据仍属于 `InvoiceRecord`。`InvoiceRecord.issue_date` 不等于 `ExpenseItem.transaction_date`；票面价税合计默认形成本地实际金额，公司限额不进入本地模型。

每个计入总额的 `InvoiceRecord` 默认生成一个 `ExpenseItem`；行程单、消费明细和重复来源副本不单独生成费用。`ExpenseItem` 不保存Concur费用类型ID、地点/VAT/付款选项ID、目标必填性、核准金额或企业自定义字段。

### 3.7 目标系统映射 `ConcurMappingProfile`

只有用户进入“上传到Concur”并选择企业档案后，系统才执行：

```text
ExpenseItem + ConcurMappingProfile(version) + 本次上传补充值
→ MappedExpensePayload
```

映射档案保存内部字段路径、外部字段ID、选项表、转换、默认值、条件必填规则和目标版本。映射缺口只影响当前目标上传，不影响本地审核与输出。切换租户或修改映射会重新生成外部投影，不得改写已审核本地费用项。

### 3.8 Concur 草稿上传会话 `ConcurUploadSession`

代表一次由用户明确触发、可恢复和可审计的“上传到 Concur”任务：

```text
upload_session_id
batch_id
tenant_profile_id
mapping_profile_version
expense_item_revisions
mapping_snapshot
upload_overrides
adapter_kind
external_report_id
report_status
expense_total
expense_created_count
field_filled_count
attachment_linked_count
failed_count
attempt_count
idempotency_key
started_at
finished_at
last_error
```

每个费用条目还必须保存 `external_expense_id`、冻结的映射输入/输出、费用创建状态、字段填写状态、附件上传/关联状态、原文件哈希、重试次数和最后错误。重试时复用已有外部标识、映射快照与幂等键，不得重复创建报销单、费用或附件。

`adapter_kind` 允许按租户能力采用已授权的官方接口、用户可见的本地辅助操作，或兼容的收据邮件降级路径。具体方式必须在技术验证后确定；任何方式都不能改变“用户在场、最终提交由用户执行”的边界。

### 3.9 输出与发送任务

本地导出和 Concur 上传都必须是关联批次、但位于批次双视图之外的独立交付任务：

- 支持幂等任务键；
- 逐项成功、失败和重试；
- 成功项不重复生成或发送；
- 结果包含文件/附件清单和哈希；
- 不把本地上传成功等同于 Concur 报销单已提交。

## 4. 目标信息架构

### 4.1 主导航

应用只保留四个主入口：

| 导航 | 用户问题 | 主要内容 |
|---|---|---|
| 工作台 | 我现在应该做什么？ | 未完成任务、新建批次、最近批次 |
| 报销批次 | 我的报销任务在哪里？ | 批次搜索、筛选、状态和继续操作 |
| 历史台账 | 这张票以前处理过吗？ | 跨批次发票记录和重复依据 |
| 设置 | 邮箱、常驻地、Concur和软件数据怎么配置？ | 来源、常驻地、Concur租户档案、数据、版本 |

“获取与处理”不再是主导航。它是已创建批次内部的一种状态。

### 4.2 批次内部页面

批次详情采用完整页面和固定页头，一级视图严格只有：

1. `费用清单`；
2. `归组`。

空批次的费用清单位置显示导入空状态；处理期间显示进度；完成处理后显示费用清单。问题、重复、待挂载材料、单条核对和审计记录均作为两个视图内的筛选、检查器或详情，不新增一级标签。导出和Concur上传不在批次内出现；完成审核后进入独立交付选择。

## 5. 完整 UI/UX 流程

### 5.1 首次启动

目标：用户不需要账号、不需要安装、不需要理解数据库或OCR。

步骤：

1. 本机准备检查：程序版本、Windows架构、数据目录、WebView2；
2. 隐私说明：数据本地处理、授权码不保存、当前数据未做应用级加密；
3. 基本资料：常驻城市；
4. 可选邮箱配置：邮箱地址和服务器配置；授权码只在需要连接时输入；
5. 完成后进入工作台。

文件导入用户可以跳过邮箱配置，仍能完成全部本地处理功能。

### 5.2 工作台

首屏优先级：

1. 中断、失败或待审核的未完成批次；
2. 主按钮“新建批次”；
3. 本月/最近待处理摘要；
4. 最近 5 个批次；
5. 当前本地数据和版本状态。

未完成批次显示动作语言：

- “继续导入”；
- “恢复处理”；
- “审核3个问题”；
- “重试2个失败输出”；
- “继续上传到Concur”或“核对2个失败项”。

不只显示“草稿”或“失败”。

### 5.3 新建批次

对话框字段：

```text
批次名称 *

[取消] [创建批次]
```

创建时间点击确认时由系统记录。创建完成立即进入该批次空状态。

验收：

- 不显示月份；
- 不显示日期范围；
- 不显示发票来源；
- 不显示邮箱或授权码；
- 不启动处理任务；
- 不产生第二个批次。

### 5.4 批次空状态

```text
这个批次还没有发票
选择一种方式导入数据，之后仍可继续添加。

[邮箱批量导入]
按日期范围从邮箱只读获取

[本地文件导入]
选择发票文件或包含发票的文件夹
```

两个入口并列、语义互斥。空状态不是错误，也不展示空表格。

### 5.5 邮箱批量导入

选择后显示：

| 字段 | 规则 |
|---|---|
| 邮箱账号 | 使用已配置账号，可切换 |
| 开始日期 | 用户选择，界面语义为包含 |
| 结束日期 | 用户选择，界面语义为包含；协议内部转换半开区间 |
| 授权码 | 当前会话没有凭据时显示，不保存 |

启动前摘要：

```text
将从掩码邮箱读取 2026-06-01 至 2026-06-30 的邮件
只使用 IMAP 读取，不修改已读、FLAGS、移动或删除邮件
结果将加入当前批次
```

用户操作：

- 主按钮“开始邮箱导入”；
- 次按钮“改用本地文件”；
- 取消返回当前批次。

### 5.6 本地文件导入

支持：

- 单个或多个发票/配套票据文件；
- 包含发票文件的文件夹递归；
- 拖放；
- PDF、OFD、XML和支持的图片格式。

不显示日期范围、邮箱和授权码，也不提供 `.eml` 选择入口。若实现层仍保留EML解析器，只能供邮箱采集内部复用或兼容迁移，不作为产品入口和发布承诺。

正式开始前预览：

- 选择的文件/文件夹数量；
- 主发票、待挂载材料、忽略和疑似重复数量；
- 明显损坏或超限文件；
- 预计形成的发票单数量；
- 自动挂载的行程单/明细数量和仍需用户选择归属的材料数量。

### 5.7 多次导入

已有费用时，费用清单右上角显示“继续导入”。

规则：

- 同一批次可以多次邮箱导入和本地导入；
- 每次导入独立记录和恢复；
- 新数据增量加入，不清空既有字段、归组和人工审核；
- 同一主发票的行程单、明细和重复来源副本挂载到同一发票单，不独立形成费用；
- 相同文件哈希或稳定发票业务键命中时折叠/标记，疑似重复默认不计入总额；
- 导入失败只影响本次导入，不损坏已有批次。

### 5.8 处理进度

页面显示阶段、数量和最近更新时间：

```text
获取票据文件   完成  115/115
聚合发票单     完成  84个发票单 · 18份配套材料 · 3份待挂载
解析字段       进行  63/84
检查重复及计入 等待
建立行程组     等待
归入其他发票   等待

[安全停止并保留进度]
```

要求：

- 用户离开页面任务继续；
- 应用重启能发现并恢复；
- 单文件失败不终止批次；
- 30秒无事件时查询后端状态，不永久停在0%；
- 失败提示包含发生了什么、已保存什么、下一步是什么。

### 5.9 费用清单

处理完成后默认进入费用清单。

建议字段：

| 列 | 内容 |
|---|---|
| 状态 | 缺失、重复、待确认、完成、排除 |
| 日期 | 交易日期；未确认时明确标注开票日期候选 |
| 票据文件 | 主发票缩略图及“行程单×N/明细×N” |
| 费用分类 | 软件内部稳定分类，不显示Concur选项 |
| 交易对方/发生地点 | 两行信息 |
| 归组 | 差旅行程、市内月份、待确认 |
| 金额 | 实际价税合计 |
| 计入状态 | 已计入、疑似重复未计入、重复未计入、用户确认非重复已计入 |
| 本地核对完成度 | 例如 `7/9`，只按软件规则 |

默认排序：

1. 关键字段缺失；
2. 疑似重复；
3. 归组待确认；
4. 未审核；
5. 已完成；
6. 已排除。

顶部支持搜索、只看问题、状态、归组和费用分类筛选；底部持续显示“已计入张数/申报总额”“疑似或确认重复未计入张数/金额”“其他排除金额”和未解决问题数。任何重复候选都不得隐藏在总额中。

### 5.10 单条费用核对

采用左右分栏：

```text
左：软件定义的费用信息 + 票据信息 + 问题与依据
右：该发票单的主发票、行程单、明细及其他配套材料查看器
```

顶部显示：

- 返回费用清单；
- 当前 `7/22`；
- 上一条；
- 下一条待处理；
- 当前费用分类、实际金额和问题数。

字段分为：

1. 费用信息：内部费用分类、实际发生日期、费用说明、交易对方、发生地点、付款方式、实际金额、币种和票面税项；
2. 票据信息：发票号码、开票日期、购销方、票种和解析证据；
3. 问题与依据；
4. 技术诊断，默认折叠。

每个本地字段显示来源：发票票面、配套材料、行程推导、软件默认、用户输入或人工修改。页面不得显示Concur选项ID、目标租户必填星号或“Concur填报字段”分组。

保存行为：

- 合法字段自动保存；
- 切换前保证已保存；
- 非法字段定位并阻止切换；
- 提供“保存并下一条待处理”；
- 显示正在保存、已保存和保存失败。

### 5.11 原件查看

必须支持：

- 图片和PDF应用内稳定预览；
- 适合宽度、适合页面和50%–250%缩放；
- PDF页码和翻页；
- 旋转；
- 可调整或折叠查看器；
- 重新加载；
- 系统默认程序打开；
- 在文件资源管理器中显示；
- 显示文件名、格式、大小和只读状态。

应用内打开失败不能只显示“无法打开文件”。用户必须能够走外部打开路径继续核对。

### 5.12 重复处理

相同发票的多个文件副本优先合并到同一发票单，费用清单只显示一行：

```text
主费用记录
来源副本 ×2 · 只计入一次
```

如果系统暂时无法确定两条记录是否是同一张发票，则保留为重复候选，但候选记录立即标记：

```text
疑似重复 · 未计入申报总额 ¥126.00
```

打开后并排比较当前记录和命中记录：

- 原件；
- 发票号；
- 日期；
- 金额；
- 销方；
- 当前/历史批次；
- 命中依据。

动作及金额结果：

- `确认重复`：保持不计入；
- `不是重复，计入总额`：必须由用户明确点击，记录审计原因后计入；
- `打开主记录/历史记录`：查看已计入对象和依据；
- `暂不决定`：继续保持不计入；
- `排除`：按其他原因不计入，可撤销。

底层文件始终保留。疑似重复不能因为用户离开页面、批次完成或上传Concur而自动恢复计入。

### 5.13 归组

归组采用“先建明确行程组，再归入其他发票”的两阶段流程。

第一阶段建立行程组：

1. 从城际铁路、航空票或已挂载行程单提取日期和城市链；
2. 形成带锚点证据的候选行程组；
3. 明确显示起止日期、城市链和用于建组的发票单；
4. 证据冲突时由用户确认、拆分、合并或新建组。

第二阶段归入其他发票：

1. 仅针对已经形成的行程组评估酒店、餐饮、出租车等发票；
2. 日期、城市和票种明确匹配时给出“建议归入”；
3. 不确定时保持“待归组”，并说明缺少的证据；
4. 配套行程单和明细随所属发票单移动，不作为独立费用被归组。

页面分为：

- 待确认；
- 差旅行程；
- 市内消费；
- 已排除。

每组显示日期、城市链、锚点发票、已归入张数、待确认张数、计入金额和形成理由。对只有“5月/6月市内消费”而没有差旅的情况，页面必须说明：

- 找到了哪些城市和日期；
- 哪些票据被视为常驻地消费；
- 是否缺少离开常驻地或返程的交通证据；
- 哪些字段为空或不可信；
- 用户如何新建、移动或合并归组。

没有明确行程锚点时不得仅凭异地商户名称自动建立差旅行程；相关发票保留在“待归组”或明确的“市内消费”集合。

不向普通用户展示规则版本和百分比置信度。

### 5.14 完成审核与交付选择

#### 5.14.1 批次内完成审核

费用清单和归组共享审核摘要：本地费用项/票据核对完成度、重复未计入数量与金额、归组状态、原件可读性和本地阻断项。批次内不显示Excel、输出包、Concur档案或上传按钮，唯一结束动作是“完成审核”。

阻断项清零且用户点击“完成审核”后，系统冻结带版本和内容摘要的 `ReviewSnapshot`，然后离开批次双视图，进入独立“交付选择”。如果用户返回批次修改费用、计入状态、票面事实、归组或附件，原快照立即失效；新的交付必须重新完成审核。

#### 5.14.2 独立交付选择

```text
审核已完成
22 笔计入费用 · CNY 8,320.08
3 笔重复未计入 · CNY 806.00

[导出 Excel]       [上传到 Concur]
使用本地稳定字段     选择企业档案并检查映射
```

两个入口是当前步骤的两个主选择，但不是永久互斥：完成一种后可以返回执行另一种。两者使用同一个有效审核快照和各自的幂等任务键；不得静默覆盖Excel，也不得重复创建Concur外部对象。交付任务和结果关联批次，但不作为批次一级视图。

“导出Excel”直接选择保存位置并预览文件名、计入费用数和总额，不要求Concur档案、映射或登录。CSV/PDF/标准目录若继续保留，只作为Excel导出流程内的次级附加格式，不在批次页或交付选择中占用第三个主入口。

“上传到Concur”进入以下流程：

1. 确认目标租户和映射档案，生成内部字段到Concur字段的预览；
2. 确认报销单草稿名称、报销单日期和可选备注；
3. 预览将创建的费用数、附件数和实际总金额；
4. 用户点击“创建草稿并上传”；
5. 系统基于审核快照冻结映射版本和本次补充值，依次创建报销单草稿、创建费用、填写映射字段、上传并关联发票、回读核对结果；
6. 失败项留在本页逐项重试，成功项不重复处理；
7. 全部完成后提供“在 Concur 中打开并检查”，由用户处理公司规则并最终提交。

#### 5.14.3 上传前检查

必须全部显示为“已就绪”或由用户明确处理：

- 所有疑似或确认重复都已从申报总额和待上传费用中排除；未决定项可以继续保留，但必须在确认页单独列出“本次不上传”；
- 需要上传的本地费用项已确认，所选目标档案的必填字段均已映射或具有明确的本次上传补充值；
- 申报金额等于发票实际价税合计；
- 每笔费用的原始发票存在、可读且格式/大小符合目标租户要求；
- 已选择并确认 Concur 租户配置档案；
- Concur 登录会话当前可用，且操作过程对用户可见；
- 目标草稿不存在未解决的同名/同幂等任务冲突。

缺失项必须直接定位到对应费用，不允许只显示“上传失败”。

如果缺失的是本地业务事实，返回单条费用核对页修正 `ExpenseItem`；如果缺失的是企业成本中心、项目号等目标专用字段，只在上传页补充或更新映射档案，不得把它写成本地费用核心字段。目标映射缺口不阻断本地输出。

#### 5.14.4 草稿级表单

本地批次名称只作为 Concur 报销单名称的默认候选，用户可在上传前修改；Concur 报销单日期由系统建议并由用户确认；备注可选。这些字段只出现在“上传到 Concur”步骤，绝不能重新放回“新建批次”。

#### 5.14.5 上传进度与结果

页面采用固定阶段条和逐项结果表：

```text
连接并确认租户
→ 创建报销单草稿
→ 创建费用条目
→ 填写费用字段
→ 上传并关联发票
→ 回读核对
```

逐项结果至少显示费用名称、金额、外部费用标识、字段状态、附件状态和错误原因。中断后再次进入该交付任务，应恢复同一个上传会话；不能重新创建第二张 Concur 报销单。

#### 5.14.6 产品边界与降级

- 软件自动化的终点是“Concur 草稿已创建且内容已核对”，不点击最终提交；
- 公司限额、VAT政策、审批规则、核准金额仍由用户在 Concur 中处理；
- 若目标租户不能使用直接草稿创建/填写能力，显示原因并允许用户改用“发送到 Concur 收据库”或导出填报包；
- 收据邮件是兼容模式，不再代表完整核心闭环；
- 适配器检测到页面或字段结构变化时必须停止，不得猜测继续填写。

### 7.5 Concur准备度缺口

目标页面确认的7个必填项：费用类型、交易日期、供应商、消费城市、金额、VAT金额、VAT计算税率。

| 字段 | 当前能力 | 缺口 |
|---|---|---|
| 费用类型 | 有本地票种 | 缺企业费用类型ID和映射档案 |
| 交易日期 | 部分有出发/入住时间 | 餐饮、市内消费等实际发生日期缺失 |
| 供应商 | 可选销售方 | 缺失处理和扩大准确率证据 |
| 消费城市 | 有可选城市 | 语义不稳定，缺Concur地点ID和省份映射 |
| 金额 | 可直接用价税合计 | 核心路径已具备；不能应用公司限额 |
| VAT金额 | 可选票面税额 | Concur字段语义和缺失规则未确认 |
| VAT税率 | 可选单税率 | 持久化、多税率和企业选项映射缺失 |

此外：

- 商务用途没有可靠业务输入；
- 付款类型只能来自用户或企业默认；
- 币种当前只能受控默认CNY；
- 省份需由消费城市映射；
- 核准金额不应由本软件填写；
- 当前只有收据邮件发送，没有报销单草稿创建、费用创建/填写和附件定向关联适配器；
- 缺少上传会话、外部报销单/费用标识、分阶段状态、幂等键和中断恢复模型；
- 缺少上传前准备度检查、逐项失败定位、局部重试和回读核对；
- Concur真实试发和租户行为仍未受控验证。

6. 公司规则、核准金额和最终提交由用户在Concur处理；
7. 邮箱只读，链接型邮件不自动访问未知URL；
8. 主发票、行程单、消费明细和其他配套材料挂载在同一个发票单下，配套材料不独立计费；
9. 行程组先由明确锚点证据形成，再判断其他发票单是否归入；
10. 疑似和确认重复默认不计入申报总额，只有用户明确标记“不是重复”后才计入；底层证据不自动删除；
11. “上传到Concur”是核心功能，包含创建报销单草稿、创建并填写费用、上传且关联发票；
12. Concur草稿创建发生在批次整理完成后，不得向“新建批次”添加Concur字段；
13. 软件只生成未提交草稿；最终提交、公司限额、核准和审批由用户在Concur处理；
14. 收据邮件和本地导出是直接草稿上传不可用时的兼容降级，不替代完整核心闭环；
15. 单条费用核对只维护软件自己的稳定费用字段，不与Concur表单字段直接绑定；
16. Concur字段只在上传时依据版本化企业配置映射生成，目标专用补充值不回写本地费用项；
17. 批次内部只包含费用清单和归组两个一级视图，问题和记录留在视图内部；
18. 导出和Concur上传只在完成审核后的独立交付选择出现，均基于有效审核快照；
19. MVP优先核心功能、Windows免安装和真实验证；
20. 用户账号、数据绑定加密和加密跨电脑备份在核心功能发布后实施。

## 13. 交付物

执行本方案最终需要形成：

- 更新后的产品UI与交互设计；
- 批次/导入任务/发票单/稳定本地费用项/审核快照/交付任务/目标映射/Concur上传会话数据模型设计；
- 页面和组件任务清单；
- Concur企业字段配置档案；
- UI状态与错误文案表；
- 自动化测试、Windows人工矩阵和真实数据验收报告；
- 公开发布缺陷清单、签名产物、哈希、SBOM和IT审核包；
- 用户使用说明：创建批次、导入、费用清单/归组审核、完成审核、选择Excel或Concur交付、在Concur检查并提交、备份和更新。

## 14. 最终完成定义

只有同时满足以下条件，产品优化才算完成：

- 用户能理解批次和导入的关系，无重复入口；
- 邮箱和本地数据都加入用户明确创建的同一批次；
- 核心票据准确、重复可解释、归组可解释、原件可访问；
- 用户能快速审核问题而不是逐张机械查看；
- 批次一级视图固定为费用清单和归组，交付操作不混入审核工作区；
- 完成审核后冻结快照，Excel和Concur交付可任意先后执行；本地修改会可靠失效旧快照；
- 单条核对中的本地费用字段稳定、来源清楚且不出现Concur术语；
- 选择目标后，Concur映射字段的来源、转换、需确认和缺失状态清楚；
- 整理完成的批次能够创建Concur报销单草稿、填写费用并正确关联原始发票；
- 上传失败可恢复且不会生成重复外部对象，结果经过Concur回读核对；
- 软件不处理公司限额，不替用户最终提交；
- Windows免安装、缩放、恢复、备份和故障路径均可验证；
- 隐私历史、签名、下载、更新和IT审核发布门禁全部关闭；
- 账号和加密延期不影响核心功能发布，也不向用户作超范围承诺。
