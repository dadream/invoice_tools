### 关键修复

#### 1. 非发票文档分类
- **问题**：酒店结账单、运单明细被误判为发票
- **影响样本**：07（结账单）、30（运单明细）、34（订单详情）
- **解决方案**：在 manifest.toml 中标记 `is_invoice = false`
- **效果**：正确排除 20 个非发票样本

#### 2. 税额标签特殊间距
- **问题**：表头"税  额"（两个全角空格）匹配失败
- **影响样本**：27
- **解决方案**：标签列表添加 `"税  额"`
- **提交**：e95bc33

#### 3. 多行明细税额求和
- **问题**：多商品明细表格只提取第一行税额，忽略其他行
- **影响样本**：04, 05, 27, 31, 36, 37, 38, 41, 43, 46, 54（11 个样本）
- **解决方案**：
  - 实现 `find_in_column_sum` 按列汇总所有明细行
  - 排除包含"合计"/"合 计"的行
  - 检测同行的"合"或"计"单字（应对碎片化版式）
- **初始结果**：通过率下降至 63.6%（回归）
- **根因诊断**：函数包含了明细行 + 合计行，导致翻倍（如 79.61 + 79.61 = 159.22）
- **最终修复**：过滤合计行后通过率恢复至 86.4%
- **提交**：dbcbe49

#### 4. 购销方名称同框提取
- **问题**：`find_buyer_seller_names` 只支持标签框和值框分离，"名称：赛比亚..."同框版式提取失败
- **影响样本**：27, 31
- **解决方案**：在邻框搜索前先用 `split("名称：")` 检查同框内值
- **效果**：PDF-VAT 通过率从 85.2% 提升至 92.6%
- **提交**：3c95e32

## 技术要点

### 空间文本框配对算法

```rust
// 同行判定：y 中心差 ≤ 15px
const SAME_LINE_TOLERANCE: f32 = 15.0;

// 右邻判定：x ≥ label.right - 5px（容忍轻微重叠）
other.x >= label_box.right() - 5.0

// 列对齐判定：x 差 ≤ 20px
(box.x - header.x).abs() <= x_tolerance
```

### 三级降级策略（税额字段）

1. **同框/同行**：`find_value()` 查找标签右侧值
2. **列求和**：`find_in_column_sum()` 汇总明细行（排除合计行）
3. **列单值**：`find_in_column()` 取第一个满足条件的值

### 合计行过滤逻辑

```rust
// 直接检测
if text.contains("合计") || text.contains("合 计") {
    continue;
}

// 碎片化版式：同行有"合"或"计"单字
let same_line_boxes: Vec<_> = boxes
    .iter()
    .filter(|b| (b.center_y() - current.center_y()).abs() <= SAME_LINE_TOLERANCE)
    .collect();

let has_total_marker = same_line_boxes
    .iter()
    .any(|b| b.text.contains("合") || b.text.contains("计"));

if has_total_marker {
    continue;
}
```

### 购销方名称双路径提取

```rust
// 路径 1：同框提取（标签和值在同一框）
if let Some(rest) = label_box.text.split("名称：").nth(1) {
    let candidate = rest.trim();
    if !candidate.is_empty() {
        return Some((candidate.to_string(), label_box.confidence));
    }
}

// 路径 2：邻框提取（标签框和值框分离，且在同一区块内）
let right_neighbors = boxes
    .iter()
    .filter(|other| {
        (other.center_y() - label_box.center_y()).abs() <= SAME_LINE_TOLERANCE
            && other.x >= label_box.right() - 5.0
            && (is_buyer_side == (other.x < MID_X))  // 区块约束
    })
    .collect();
```

## 剩余问题分析

### 未通过样本（4/44）

#### 样本 48：OFD 纯值布局
- **现象**：文本框只有值，无标签（如 "74.00" 的框附近没有"价税合计"）
- **根因**：某些开票平台使用固定位置布局，依赖坐标而非标签
- **解决方案**：需要位置推断（"x=A, y=B 的框 → total_amount 字段"）或模板匹配
- **优先级**：低（1 个样本，ROI 不高）

#### 样本 06：Identity-H 编码 panic
- **现象**：`pdf-extract` 库断言失败 `assertion failed: name == "Identity-H"`
- **状态**：已用 `catch_unwind` 容错，样本未填写预期值，暂不在统计中
- **根因**：PDF 同时包含 UniGB-UCS2-H 和 Identity-H 两种编码，库内部硬断言
- **解决方案**：等待 `pdf-extract` 库修复，或切换到 `pdfium` / `mupdf` 绑定
- **优先级**：中（1 个样本，需要外部依赖）

#### 样本 01, 02：文件损坏
- **现象**：
  - 样本 01：PDF trailer 损坏，`lopdf` / `pdf-extract` 均无法加载
  - 样本 02：OFD ZIP 中央目录损坏，`zip` crate 无法打开
- **解决方案**：无（文件本身不可读）
- **优先级**：无（不可修复）
