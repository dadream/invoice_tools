# Concur 浏览器交付与内置测试

状态：浏览器交付实现与自动化夹具验证；真实企业租户尚需用户测试。本文覆盖历史文档中“必须取得 OAuth 凭据”“一批次一报销单”“材料合并为一个 PDF”的浏览器交付假设。原 API 方式保留为高级测试，不与浏览器方式混用进度。

## 1. 用户边界

- 用户使用电脑已安装的 Edge，手动登录门户、选择公司账号、完成 MFA。不能取得官方应用凭据时，不再要求 Client ID/Secret。
- 这是操作用户有权限使用的网页，不是获得官方 API 权限；企业禁止自动浏览器时停止，不绕过终端、身份或权限限制。
- 软件只创建未提交草稿，不执行提交、审批、政策确认或删除。
- 实际金额保持票面值，例如 126 元，不应用公司的 80 元餐费上限。VAT、付款类型、城市等选项需用户确认，不能臆造或用零掩盖缺口。

## 2. 对象关系

| 本地对象 | Concur 对象 | 规则 |
|---|---|---|
| 所有本地消费组 | 一张本地费用草稿 | 不按月份再拆单 |
| 所有差旅行程组 | 一张差旅费用草稿 | 不按每趟行程再拆单 |
| 其他组，例如物流 | 交付阶段选择上述目标之一 | 不改核心归组 |
| 一个已计入稳定费用 | 一条费用 | 类型、日期、金额、交易方等经映射填写 |
| 发票/行程单/水单/明细 | 对应费用下逐份追加的附件 | 配套材料不重复产生费用或金额 |

存在两类费用时创建两张草稿；只有一类时只创建一张。排除项、疑似重复、duplicate_copy 不上传。同费用重复内容只上传一份；同发票来源、同角色的 PDF/OFD 优先使用 PDF。没有支持的独立格式时明确阻止开始，不静默遗漏。

## 3. 架构

```text
核心 LedgerDb 的已审核快照（只读）
        ↓ App shell 适配
invoice-delivery-contract：目标无关 Snapshot / Expense / Document
        ↓
invoice-concur：表单映射、两类拆单、冻结计划、私有数据库表、防重和恢复
        ↓ App shell 的私有 stdio 通道
concur-browser：可见 Edge、DOM 字段读取、填表、保存后回读、附件追加验证
```

核心模块不依赖 invoice-concur，也不保存 Concur 专属字段。新增核心接口仅用于读取快照内冻结的归组，不能用当前可变归组替代审核结果。

- `crates/invoice-delivery-contract`：中立数据契约，没有数据库或 Concur 依赖。
- `crates/invoice-concur`：不导入任何 invoice-store 类型，拥有 `concur_browser_profiles` / `concur_browser_jobs` 表；不更改核心 `user_version`。
- `src-tauri/src/commands/concur_browser.rs`：组装层，桥接只读快照和浏览器。每个外部步骤执行前检查快照仍有效。完成后通过现有通用交付接口登记结果。
- `sidecars/concur-browser`：独立 npm 锁文件、Playwright Core、合成测试集。通过 stdio 通信，不开放 HTTP 控制端口。
- `ui/src/features/concur`：连接、映射、计划、结果四步界面。设置页进入测试模式，批次完成审核后的交付页进入真实模式。

浏览器运行时和样例不放在业务备份内；映射、进度随用户数据库备份。恢复时只按材料 ID 与 SHA-256 重定位同一材料，不按名称替换事实。浏览器不导出 Cookie、密码或 OAuth 令牌；浏览器会话关闭后需重新登录。

## 4. 映射与执行

首次由用户分别打开创建报销单和各类费用表单，软件读取实际可编辑标签、必填标记、控件类型和选项。标签只用于页面定位；稳定字段路径、固定值和选项转换单独保存。原生下拉选项可直接选择；远程联想城市等选项需提供准确名称并在填表时选择实际选项。

日期支持 ISO 和月/日/年格式。金额和日期必须直接来自稳定字段，不允许用常量替换金额。恢复标记写入报销单名称及费用备注，用于回读身份确认。相同账号、租户下重复保存未修改的映射复用原版本；实际内容变化才生成新版本。已冻结计划不随之后配置变化。

预检检查：已计入费用、目标组、表单映射、必填值、选项、附件类型/大小/摘要。每份文件先采用保守 5 MB 上限，实际企业限制更严时以页面结果为准。

步骤状态为 `pending → writing → verified`。先落盘 writing，再操作网页；只有保存、刷新并回读值或附件关联成功才成为 verified。未测、失败和需要用户处理不等于通过。每个附件验证本文件及之前已经追加的文件仍然存在。

无法确定保存结果时：用户打开对应页面，点击“刷新回读并核对本页”。只有用户在 Concur 确认尚未保存后，才允许重试。绝不因超时自动重建。暂停在当前步骤完成后生效；恢复继续未完成步骤。一个报告完成后其结果保留，后续失败不重新创建已完成报告。

同一账号/租户下，同一批次只能有一个持久交付计划，即使重新审核也不能盲目新建另一套远端费用。旧快照失效时禁止继续写入；涉及旧草稿处理必须先人工协调，不能自动删除或覆盖。

## 5. 随包测试实例

目录：`concur-browser/samples/`。包含 `sample.json`、使用说明和 6 份标记“测试样例·请勿报销”的 PDF。费用均为虚构，不含真实邮箱、发票号码、税号或个人信息，不加入真实批次，也不参与去重。

| 草稿 | 费用 | 金额 | 附件 |
|---|---|---:|---|
| 本地费用 | 市内交通 | 1.11 | 发票样例 |
| 差旅费用 | 火车 | 2.22 | 发票样例、行程单 |
| 差旅费用 | 住宿 | 3.33 | 发票样例、水单、明细 |

预期共 2 张未提交草稿、3 条费用、6 份独立附件，合计 CNY 6.66。开始前必须勾选测试写入授权。用户测试后在 Concur 删除测试草稿，不能提交。

真实批次交付必须已有同一账号、租户和完整映射内容的已通过测试。测试有效性忽略数据库版本号，兼容旧版本重复保存产生的相同映射；账号、租户、表单结构、字段、选项、日期格式、费用类型或交付归属实际改变后仍需重新测试。未完成、结果不确定和正式交付记录不能充当测试通过记录。合成页面自动化测试不会写入通过记录，不能替代用户实际租户测试。

## 6. 当前适配范围与限制

- 支持标签可读取的标准输入、原生下拉、联想选择、复选框；企业页面定位不唯一、字段结构变化、特殊控件或额外明细要求时暂停。
- 住宿 Itemization、参加人、公司自定义复杂明细未通用自动生成。若企业要求这些内容，由用户在页面完成，再回读；不能宣称对应企业全自动兼容。
- 费用保存后须能打开具有字段和所属报销单身份的详情；附件须能读到文件清单。页面不暴露这些确认依据时不会判定成功。
- 每步刷新回读用于检查已保存结果，不把页面上尚未保存的输入值当作成功。
- 本版本原始文件优先逐份上传；独立 OFD 未转换且无对应 PDF 时需先准备独立 PDF。不能回退为将所有材料合并上传。
- 只验证隔离合成页面不代表真实 Concur 已兼容。公司浏览器政策、Concur 改版、企业字段和附件策略都以用户测试结果为准。

## 7. 构建与验收

新增 Rust 测试覆盖拆单、金额、VAT 缺口、附件去重、版本化映射、并发状态更新、防重与中断恢复；Node 测试用已安装 Edge 的无界面模式，拦截所有请求为合成页面，验证完整流程及附件覆盖检测。前端测试保证未测/不确定不计为通过。

`scripts/stage-concur-browser.ps1` 将锁定 Node、浏览器运行库、许可和完整样例复制到 EXE 同级。运行时总量限制 256 MiB；不附带测试源码、npm 缓存、完整浏览器或真实用户数据。CI 按独立锁文件安装库，不下载浏览器。

用户验收顺序：连接账号 → 确认已读取报销单 → 逐类读取/保存映射 → 检查示例 → 确认写入 → 检查两张草稿/三条费用/六份材料 → 暂停与继续 → 删除测试草稿 → 再使用真实批次。
