# Concur 字段映射方案

> **当前状态（2026-09-03）：** 本文仍是 Concur 目标字段和映射缺口的专项基线；本地映射/预检已实现，但指定租户的真实草稿创建、费用填写、附件关联和回读尚未验证。不得把模拟会话或禁用态表述为真实上传成功。

> 文档状态：字段盘点、映射边界与缺口基线
> 版本：v1.4
> 更新日期：2026-09-03
> 适用范围：当前用户提供的 Concur 单条报销明细页面，以及本仓库当前发票采集、解析、审核能力

## 1. 目标

本文档明确以下内容：

1. 当前 Concur 单条报销明细需要填写的表单字段；
2. 截图中能够确认的必填项；
3. 当前软件已经能够自动提取或推导的字段；
4. 软件字段与 Concur 字段之间的映射关系；
5. 仍需人工输入、企业配置或继续开发的缺口；
6. 报销单草稿、费用条目和发票附件的创建/关联要求；
7. 后续开发和验证的验收口径。

本文档是目标映射配置、上传预检、字段适配器和 Concur 填充验证的共同输入。单条费用审核使用软件自己的稳定费用模型，不直接使用本文列出的Concur字段。只有用户完成批次审核、生成有效审核快照，并在独立交付选择中点击“上传到Concur”后，本文映射才参与处理；Excel导出不依赖本文配置。本文不把截图中的示例值、报销限额或税务处理结果当成通用产品规则。

## 2. 产品责任边界

### 2.1 软件负责

- 获取并保存原始发票附件；
- 解析发票票面实际信息；
- 根据票种、行程信息和用户输入建立目标系统无关的本地 `ExpenseItem`；
- 在用户选择目标企业档案后，通过版本化配置把本地字段映射为Concur字段候选；
- 在填入 Concur 前，让用户检查映射缺失、目标专用补充值和低置信来源；
- 按发票实际价税合计填写申报金额；
- 保留原始值、自动生成值和人工修正值的审计关系；
- 在用户确认后创建 Concur 报销单草稿；
- 逐条创建费用并填写已冻结映射投影中的目标字段值；
- 上传原始发票并与对应费用条目建立一对一关联；
- 回读创建、填表和附件关联结果，失败时局部重试且不重复创建；
- 当直接草稿上传不可用时，将票据发送至 Concur 收据库作为兼容降级；
- 最终提交前保持用户可见、可检查，由用户执行最终提交。

### 2.2 软件不负责

- 不计算或执行企业餐费、住宿费、交通费等报销上限；
- 不因公司限额把发票实际金额从 126 元调整为 80 元；
- 不判断企业最终可报金额、可抵扣税额或审批金额；
- 不替用户接受企业政策、完成最终提交或审批；
- 不把某个 Concur 租户的费用类型、税率选项和必填规则硬编码为通用规则。
- 不在单条费用核对页显示或持久化Concur字段名称、选项ID、目标必填性和企业自定义字段。

金额基准固定为：

```text
软件初始申报金额 = 发票票面价税合计
企业限额调整、税务调整、最终核准 = 用户进入 Concur 后处理
```

### 2.3 三层字段架构

```text
InvoiceRecord                 票面事实和原件证据
    ↓ 归一化/人工核对
ExpenseItem                   软件稳定费用字段
    ↓ 选择目标 + ConcurMappingProfile(version) + UploadOverrides
MappedExpensePayload          一次上传的外部字段投影
    ↓
Concur Report / Expense / Attachment
```

- `InvoiceRecord` 与 `ExpenseItem` 是可备份、可本地输出、跨租户稳定的核心数据；
- `ConcurMappingProfile` 保存内部字段路径到外部字段ID、选项、转换、默认值和条件必填规则；
- `UploadOverrides` 只保存成本中心、项目号等本次/目标专用补充值；
- `MappedExpensePayload` 是上传会话中的冻结快照，不是核心费用记录；
- 切换租户或更新映射只重新生成投影，不得修改已审核 `ExpenseItem`。

## 3. Concur 页面与字段盘点

### 3.1 必填判断口径

- “明确必填”表示用户截图中的字段标签带红色 `*`；
- “截图未标必填”只表示当前截图没有红色 `*`，不代表其他公司或其他费用类型一定选填；
- Concur 字段必填性、选项和自定义字段可以按企业租户配置变化；
- 开发前必须用目标用户的实际 Concur 页面再执行一次配置探测。

### 3.2 报销单级上下文

| 页面内容 | 截图表现 | 是否是单条明细字段 | 当前软件来源 | 说明 |
|---|---|---:|---|---|
| 费用报告名称 | 创建报销单页面带红色 `*` | 否 | `Batch.name` | **明确必填**；本地批次名称作为默认候选，只在“上传到Concur”页面确认或修改 |
| 费用报告日期 | 创建报销单页面日期字段 | 否 | 系统建议 + 用户确认 | 截图未标必填；默认建议当前日期，不属于本地批次字段 |

## 4. 当前软件可提供的数据

当前解析器统一输出模型为 `ParsedInvoice`，审核后持久化为 `ReportedInvoice`。当前字段能力如下。

| 软件字段 | 当前能力 | 数据性质 | 当前验证边界 |
|---|---|---|---|
| `invoice_number` | 自动提取 | 发票号码 | 真实 QQ 当前批次的核心字段之一；84/84 匹配仅代表该批次 |
| `issue_date` | 自动提取 | 开票日期 | 不是通用的交易日期 |
| `total_amount` / `amount` | 自动提取 | 发票价税合计 | 真实 QQ 当前批次核心字段已核对；必须使用十进制定点金额 |
| `tax_amount` | 可自动提取，允许为空 | 发票票面税额 | 尚不能声明跨格式、跨票种完整覆盖 |
| `tax_rate` | 可自动提取，允许为空 | 发票票面税率 | 当前持久化审核模型未保存该字段，且单值模型不能完整表达多税率发票 |
| `buyer_name` | 可自动提取，允许为空 | 购买方名称 | 不对应截图中的必填字段，但可用于票据归属检查 |
| `seller_name` | 可自动提取，允许为空 | 销售方名称 | 可作为供应商名称候选 |
| `ticket_type` | 自动分类 | 铁路、飞机、酒店、市内交通、餐饮、其他 | 不是 Concur 费用类型，需要企业映射 |
| `city` | 可提取或推导，允许为空 | 当前模型定义的票据关联城市 | 交通票目前偏向出发城市；不一定等于 Concur 的消费城市 |
| `departure_time` | 可提取，允许为空 | 交通票出发时间 | 有值时可提供交易日期候选 |
| `checkin_date` | 可提取，允许为空 | 酒店入住日期 | 有值时可提供酒店交易日期候选，最终语义仍需确认 |
| `InvoiceRecord.documents[]` | 自动保存 | 主发票、行程单、消费明细及其他配套材料 | 同一发票单的文件集合；配套材料不独立创建费用，定向关联具体费用条目是发布前核心缺口 |
| `parse_level`、`confidence` | 自动生成 | 解析来源与置信度 | 只用于审核和风险控制，不填入 Concur |
| 批次名称、月份、归组结果 | 已有 | 报销批次和行程上下文 | 可用于生成报销单名称、商务用途候选和明细顺序 |

上述是当前解析输入，不是长期费用数据契约。目标本地费用模型固定为：

| `ExpenseItem` 字段 | 稳定语义 | 典型来源 | 是否允许存Concur值 |
|---|---|---|---:|
| `category_code` | 软件内部费用分类 | 票种规则 + 用户确认 | 否 |
| `transaction_date` | 实际业务发生日期 | 出发/入住/明细日期 + 用户确认 | 否 |
| `description` | 用户理解的费用说明 | 批次/行程模板 + 用户输入 | 否 |
| `counterparty_name` | 实际交易对方或服务商 | 销售方/承运方 + 用户确认 | 否 |
| `location` | 国家、省、市代码及显示名 | 票面/行程/用户选择 | 否 |
| `payment_method` | 软件内部付款方式枚举，可为未知 | 用户默认或输入 | 否 |
| `gross_amount` | 实际费用金额 | 票面价税合计 | 否 |
| `currency_code` | ISO 4217币种 | 产品范围/票面/用户确认 | 否 |
| `tax_details[]` | 票面税种、税率和税额 | 发票解析 + 用户确认 | 否 |
| `trip_group_id` | 本地明确行程组 | 归组结果 | 否 |
| `inclusion_status` | 是否计入本地申报总额 | 去重/用户决定 | 否 |
| `field_provenance` | 字段来源、确认和修改历史 | 系统审计 | 否 |

Concur费用类型ID、地点/VAT/付款/票据状态选项ID、目标必填标记、核准金额、成本中心和项目号不属于 `ExpenseItem`。

真实 QQ 验证已经证明当前批次 84 份有效发票均能生成结构化结果，且发票号码、开票日期、价税合计三个核心字段共 252 个槽位全部匹配。该结果不能外推为税额、税率、名称、城市的 100% 准确率，也不能外推为其他邮箱、月份和票种的总体准确率。

## 5. 字段映射矩阵

状态定义：

- **直接自动**：当前字段语义一致，可以直接映射；
- **条件自动**：当前软件有候选数据，但需要票种规则、企业配置或用户确认；
- **默认生成**：发票不包含该信息，由产品范围或用户配置提供默认值；
- **人工补充**：当前无法可靠得到；
- **不填写**：属于 Concur 计算、审批或只读结果。

| Concur 字段 | 必填性 | 软件来源 | 映射方式 | 当前状态 | 缺口与处理规则 |
|---|---|---|---|---|---|
| 费用类型 | **明确必填** | `ExpenseItem.category_code` | 内部分类 → 企业 Concur 费用类型稳定ID | **条件自动** | 缺企业费用类型选项及映射表；禁止只靠显示文本硬编码 |
| 交易日期 | **明确必填** | `ExpenseItem.transaction_date` | 日期格式转换后填入 | **直接/需确认** | 该本地字段必须先按软件语义核对；开票日期不得静默替代 |
| 商务用途 | 截图未标必填 | `ExpenseItem.description`，或上传模板/补充值 | 按档案规则直接、拼接或要求上传时补充 | **条件自动** | 目标字段语义可能比本地费用说明更窄；不得为了某租户改名本地字段 |
| 供应商名称 | **明确必填** | `ExpenseItem.counterparty_name` | 规范化后填入 | **条件自动** | 本地字段允许明确“未知/待确认”；目标必填时只阻断上传 |
| 消费城市 | **明确必填** | `ExpenseItem.location` | 内部城市代码 → Concur 地点选项ID | **条件自动** | 需要地点选项表和同名城市消歧；外部ID不回写本地地点 |
| 付款类型 | 截图未标必填 | `ExpenseItem.payment_method` 或企业默认 | 内部枚举 → 企业付款选项ID | **默认生成/人工补充** | 发票不能可靠推断时本地可为unknown，目标上传时补充或取档案默认 |
| 金额 | **明确必填** | `ExpenseItem.gross_amount` | 精确小数直接映射 | **直接自动** | 不应用公司报销上限；金额冲突必须先回本地审核 |
| 币种 | 截图未标必填 | `ExpenseItem.currency_code` | ISO代码 → 目标币种选项 | **直接/条件自动** | 不得在适配器中无条件固定CNY |
| VAT 金额 | **明确必填** | `ExpenseItem.tax_details[]` | 经目标VAT语义和多税率规则转换 | **条件自动** | 未确认目标语义时不得映射或无依据填0；不改变本地票面税项 |
| 核准金额 | 截图未标必填 | 无 | 不映射 | **不填写** | Concur 审批或计算结果，只读 |
| 票据状态 | 截图未标必填 | `InvoiceRecord.documents[]`及本地票据核对状态 | 本地状态 → 企业票据状态选项ID | **默认生成** | 目标选项只存在映射档案；解析成功不等同于税务真实性 |
| 私人费用 | 截图未标必填 | 上传档案默认或本次补充值 | 默认否，必要时上传阶段确认 | **默认生成** | 属于目标声明，不进入 `ExpenseItem`；本地不计入使用独立 `inclusion_status` |
| 州/省 | 截图未标必填 | `ExpenseItem.location.province_code` | 行政区代码 → Concur地点/省份选项ID | **条件自动** | 外部选项ID不回写本地地点 |
| VAT 计算税率 | **明确必填** | `ExpenseItem.tax_details[].rate` | 票面税率集合 → 企业VAT选项 | **条件自动** | 多税率和目标语义必须由映射规则明确；缺失只阻断上传 |
| 备注 | 截图未标必填 | 上传档案模板或本次补充值 | 默认空；需要时在上传页填写 | **人工补充** | 目标专用备注不写入本地费用说明，除非用户明确修改本地事实 |
| 发票及配套附件 | 条件必需 | `InvoiceRecord.documents[]` | 主发票及其行程单/明细上传并关联同一目标费用ID | **字段来源需聚合，适配待开发** | 配套材料不得创建独立费用；当前收据库发送不能证明已关联指定费用，发布前必须实现并回读验证 |

### 5.1 报销单草稿级映射

| Concur字段 | 必填性 | 软件来源 | 填写规则 | 上传结果要求 |
|---|---|---|---|---|
| 费用报告名称 | **明确必填** | `Batch.name` | 作为默认值，用户在上传页可修改 | 保存Concur返回的报销单ID和最终名称 |
| 费用报告日期 | 截图未标必填 | 当前日期建议 | 用户确认后填写 | 保存最终日期，不回写为批次创建时间 |
| Comment | 截图未标必填 | 无 | 默认空，用户可填写 | 保存最终文本 |
| 报销单状态 | 只读 | Concur返回 | 不填写 | 必须核对为未提交/草稿语义，不能显示为已提交 |

本地“新建批次”仍然只包含批次名称和系统创建时间。批次内部只有费用清单和归组两个一级视图；完成审核后进入独立交付选择。报销单日期、Comment、目标租户及其他Concur字段只在用户选择“上传到Concur”后的上传页面出现，不得进入批次审核或Excel导出。

### 5.2 创建与附件关联关系

目标对象关系固定为：

```text
1 个本地 Batch
→ 1 次可恢复的 ConcurUploadSession
→ 1 个 Concur Report Draft
→ N 个 Concur Expense Entry
→ 每笔 Expense Entry 关联其发票单中的主发票及全部配套附件
```

每个计入总额的 `InvoiceRecord` 默认只创建一个费用条目。行程单、消费明细、其他配套材料和重复来源副本不得单独创建费用；疑似或确认重复的发票单默认不创建Concur费用，只有用户明确确认“不是重复，计入总额”后才进入待上传集合。

每个外部对象都必须记录Concur返回的稳定标识、当前阶段、最后核对时间和幂等键。重试只补齐缺失阶段，不得重新创建已成功的报销单、费用或附件。若Concur返回结果未知，状态必须为“需要核对”，不能当作失败后直接重建。

## 6. 明确必填项及缺口

截图可以确认 7 个必填字段。

| 必填字段 | 当前可自动化程度 | 是否存在缺口 | 缺口级别 | 结论 |
|---|---|---:|---|---|
| 费用类型 | 有票种，缺企业映射 | 是 | P0 | 开发前取得实际费用类型选项，并建立可导入/导出的映射配置 |
| 交易日期 | 部分票种有候选 | 是 | P0 | 增加通用业务发生日期；未得到真实日期时必须人工确认，不能使用开票日兜底 |
| 供应商名称 | 可从销售方提取 | 是 | P0 | 对缺失和低置信名称提供人工输入；补充真实字段准确率验证 |
| 消费城市 | 有可选城市字段 | 是 | P0 | 明确不同票种的城市语义，增加地点选择和 Concur 地点 ID 映射 |
| 金额 | 可直接提取价税合计 | 否（解析成功时） | 已覆盖核心路径 | 始终填实际价税合计，不执行公司限额；异常进入审核 |
| VAT 金额 | 可提取票面税额，但允许为空 | 是 | P0 | 确认 Concur 字段语义，完善缺失税额处理和准确率证据 |
| VAT 计算税率 | 可提取但允许为空 | 是 | P0 | 持久化税率，支持多税率或明确拆分规则，并建立租户 VAT 选项映射 |

因此，当前 7 个明确必填项中：

- 1 项可在解析成功时直接稳定映射：金额；
- 3 项具有候选数据但仍缺配置或覆盖保证：费用类型、供应商名称、消费城市；
- 1 项仅在部分票种具备可靠候选：交易日期；
- 2 项存在字段语义、持久化或企业选项缺口：VAT 金额、VAT 计算税率。

在这些 P0 缺口关闭前，软件可以生成 Concur 填报草稿，但不能宣称所有必填项都能全自动填写。

## 7. 非必填字段的产品处理

| 字段 | MVP 处理 | 何时升级为 P0 |
|---|---|---|
| 商务用途 | 使用“日期 + 行程/批次 + 票种”生成草稿，允许用户修改 | 目标租户将其配置为必填时 |
| 付款类型 | 用户首次选择后记为个人或企业配置默认值 | 目标租户将其配置为必填时 |
| 币种 | 中国境内发票默认 CNY | 产品支持外币发票时 |
| 票据状态 | 有有效发票附件时默认“发票” | 租户选项无法映射或有附加规则时 |
| 私人费用 | 默认不勾选，用户在 Concur 中可修改 | 企业要求显式确认时 |
| 州/省 | 由消费城市联动生成 | 目标租户将其配置为必填时 |
| 备注 | 默认空 | 目标租户将其配置为必填或异常必须说明时 |
| 核准金额 | 永不填写 | 不升级；始终由 Concur 产生 |

## 8. Concur 企业配置档案

各公司的 Concur 字段和选项不同，映射必须配置化。企业档案既描述目标字段，也明确每个目标字段从哪个本地字段生成：

```json
{
  "schema_version": 1,
  "mapping_version": "2026-08-26.1",
  "profile_name": "目标公司-Concur配置",
  "concur_ui_version": "nextgen",
  "observed_at": "2026-08-25",
  "fields": {
    "expense_type": { "required": true },
    "transaction_date": { "required": true },
    "vendor_name": { "required": true },
    "purchase_city": { "required": true },
    "amount": { "required": true },
    "vat_amount": { "required": true },
    "vat_rate": { "required": true },
    "business_purpose": { "required": false },
    "payment_type": { "required": false },
    "province": { "required": false },
    "comment": { "required": false }
  },
  "field_mappings": {
    "transaction_date": { "source": "ExpenseItem.transaction_date", "transform": "date_iso" },
    "vendor_name": { "source": "ExpenseItem.counterparty_name", "transform": "trim" },
    "amount": { "source": "ExpenseItem.gross_amount", "transform": "decimal_2" },
    "currency": { "source": "ExpenseItem.currency_code", "transform": "option_lookup" },
    "purchase_city": { "source": "ExpenseItem.location.city_code", "transform": "location_option_lookup" }
  },
  "expense_type_mapping": {
    "meal": {
      "concur_option_id": "待探测",
      "concur_option_label": "销售费用-国内差旅费-餐费"
    }
  },
  "defaults": {
    "is_personal": false
  }
}
```

正式实现时不得依赖中文显示名称作为唯一键。可取得外部 ID 时保存 ID；只能通过 UI 填充时，同时保存稳定标签、层级路径和探测版本，并在标签变化时停止自动填充、要求重新确认。字段映射必须引用受支持的内部字段路径，不允许执行任意脚本；转换器使用白名单和确定性版本。

企业配置档案允许同事之间导出/导入，但不得包含：

- Concur 用户名、密码、Cookie 或会话令牌；
- 邮箱授权码；
- 发票、金额、客户和行程等个人报销数据；
- 企业餐费、住宿费等限额规则。

## 9. 审核与交互要求

### 9.1 单条费用核对页

页面继续采用左侧表单、右侧原始票据查看器，但左侧只包含：

1. `费用信息`：稳定 `ExpenseItem` 字段及来源/确认状态；
2. `票据信息`：发票号码、开票日期、购销方和解析证据；
3. `问题与依据`：重复、归组、字段冲突和人工修改记录。

不得在该页面显示Concur字段名、外部选项ID、目标租户必填星号、成本中心或项目号。开票日期与实际发生日期并列说明；实际金额使用发票价税合计；票面税项无可靠值时不得静默填0。单条费用是否核对完成由软件的本地规则决定，与选择哪个Concur租户无关。

### 9.2 上传到Concur预检页

用户选择目标企业档案后，每个目标字段显示以下状态之一：

- 已由本地字段直接映射；
- 已通过选项表/转换生成；
- 需要更新映射配置；
- 需要本次上传补充；
- 不由本软件填写；
- 目标字段漂移，已停止自动填充。

每一行同时显示“内部来源字段 → 转换/选项映射 → Concur目标字段 → 最终值”，并提供两类解决动作：

- 本地业务事实错误：返回单条费用核对并修改 `ExpenseItem`；
- 目标专用字段缺失：更新企业档案或填写 `UploadOverrides`。

目标映射缺口只阻止当前Concur上传，不阻止本地审核完成和Excel/CSV/PDF输出。上传开始前冻结费用项revision、映射版本、补充值和最终投影；完成后按同一快照回读对账。

## 10. 当前实现缺口

除字段数据缺口外，当前仓库还存在以下实现缺口：

| 缺口 | 当前情况 | 目标 |
|---|---|---|
| 稳定本地费用项 | 当前审核持久化以发票字段为主，旧方案拟直接增加Concur字段 | 建立版本化 `ExpenseItem`，与任何目标系统字段解耦 |
| Concur 草稿上传适配器 | 当前主要实现收据邮件发送 | 创建报销单草稿、创建/填写费用、上传并关联发票、回读核对；最终提交仍由用户完成 |
| 租户字段探测与映射 | 尚无正式配置模型 | 记录目标字段ID、必填性、选项、内部来源路径、转换、默认值和页面版本 |
| 费用分类与目标类型 | 仅有本地 `TicketType` | 建立软件稳定 `category_code`，再配置映射到Concur费用类型选项 |
| 实际发生日期模型 | 只有开票日、部分出发/入住日期 | 新增本地统一 `ExpenseItem.transaction_date`、来源和确认状态 |
| 币种模型 | `ParsedInvoice` 无币种 | 增加本地 `ExpenseItem.currency_code`，适配器不得无条件固定CNY |
| 税项持久化 | 解析模型有可选税率，审核持久化模型没有 | 保存本地票面 `tax_details[]`；Concur VAT语义由映射层处理 |
| 地点与目标选项 | 城市字段可空且语义按票种变化 | 增加本地结构化地点，再映射到Concur地点选项 |
| 字段级来源与确认 | 当前主要是整张票的解析等级和置信度 | 为每个本地字段保存来源、置信度、人工确认和修改历史 |
| 映射快照与隔离 | 当前没有 | 保存费用项revision、映射版本、补充值和最终投影；映射不反写本地 |
| 明细/自定义字段探测 | 截图未覆盖 | 登录目标租户逐费用类型核对并纳入配置档案 |
| 报销单和费用外部ID | 当前没有完整模型 | 保存外部ID、阶段状态、幂等键、重试次数和最后错误 |
| 附件与费用条目关联 | 当前附件进入收据库 | 实现并回读验证附件一对一关联到对应费用明细 |
| 中断恢复与防重 | 收据邮件有部分防重，草稿流程没有 | 未知状态先核对；恢复同一会话；成功步骤不重复执行 |

## 11. 开发优先级

### P0：Concur 草稿上传核心闭环发布前必须完成

1. 建立版本化 `ExpenseItem`，迁移当前审核字段并保证不含Concur字段名、选项ID或目标必填性；
2. 单条费用核对改为“费用信息/票据信息/问题与依据”，移除Concur字段与企业必填星号；
3. 用目标租户核对截图中的7个必填字段，并检查页面下方、明细标签页及条件字段；
4. 导出或人工记录费用类型、VAT税率、付款类型、票据状态、城市/省份选项；
5. 建立版本化企业配置档案、内部字段路径和确定性转换/选项映射；
6. 增加本地实际发生日期、币种、结构化地点、票面税项、字段来源和确认状态；
7. 明确Concur VAT金额、VAT计算税率的租户语义；
8. 在上传预检页增加外部必填缺口、本次补充值和映射预览，不回写本地费用项；
9. 建立映射快照、报销单/费用/附件外部ID及幂等状态模型；
10. 实现创建报销单草稿、逐条创建费用、映射字段填写和附件关联；
11. 建立跨两个映射档案的本地零变化、回读核对、中断恢复、未知状态和局部重试测试；
12. 建立字段填充和附件关联后的逐项对账测试，但不自动点击最终提交。

### P1：首个租户可用后补充

1. 商务用途模板和用户常用值；
2. 付款类型默认值；
3. 城市到省份的自动联动；
4. 配置档案导出、导入和版本兼容；
5. 更多费用类型和条件字段覆盖。

### P2：跨公司推广前补充

1. 多租户页面版本适配；
2. 配置漂移检测；
3. 多税率、外币和汇率字段；
4. 成本中心、项目号、参与人、分摊和逐项明细等企业自定义字段。

## 12. 验收标准

首个 Concur 草稿上传版本必须同时满足：

1. 单条费用核对只维护稳定 `ExpenseItem` 和 `InvoiceRecord` 字段，不出现Concur字段名称、选项ID、目标必填性或企业自定义字段；
2. 截图中7个明确必填字段全部进入 `ConcurMappingProfile` 和上传预检，而不是进入本地费用核心模型；
3. 每个目标必填字段都有明确内部来源和映射规则，或明确标记为上传补充，不能空值静默跳过；
4. 金额严格等于发票实际价税合计，不能应用企业报销上限；
5. 开票日期不得在无提示的情况下作为实际发生日期；
6. 费用类型使用内部分类到企业稳定选项ID的已确认映射；
7. VAT金额和税率在目标字段语义确认后才能从本地票面税项映射；
8. 每个自动字段可以追溯到费用项revision、原始发票、映射规则、档案版本或上传补充值；
9. 低置信本地事实返回单条核对；目标必填映射缺口只阻止当前Concur上传，不阻止本地输出；
10. 同一本地费用项切换两个租户/映射档案后，本地字段、审核状态和本地输出零变化；
11. 软件不点击Concur最终提交，用户能够在Concur中调整公司政策相关内容；
12. 字段填充测试按“原始发票→本地费用项→冻结映射投影→Concur回读值”四层逐项对账；
13. 当前租户新增或改变必填字段时停止自动填充并要求更新配置档案，不修改本地费用项；
14. 配置档案不包含账户凭据、会话信息或个人发票数据；
15. 创建一个未提交报销单草稿，并保存Concur返回的稳定报销单ID；
16. 每笔已选费用只创建一次，外部字段值与冻结映射投影逐项一致；
17. 每个原始发票只关联到正确费用条目，错关联和漏关联均为0；
18. 中断、重复点击和失败重试不产生重复报销单、费用或附件；
19. 未知外部状态先回读或要求人工核对，不得盲目重建；
20. 完成后Concur保持未提交草稿，并提供用户打开检查的明确入口。

## 13. 需要后续现场确认的项目

以下问题不能仅凭当前两张截图确定，必须在目标 Concur 租户中确认：

1. “明细”标签页是否包含必填的逐项拆分字段；
2. 不同费用类型是否会动态出现成本中心、项目号、参与人、里程等字段；
3. 商务用途、付款类型、州/省和备注在其他费用类型下是否变为必填；
4. VAT 金额表示票面税额、可抵扣税额还是企业申报税额；
5. VAT 税率选项是否允许按票面税率填写，以及一张多税率发票如何处理；
6. 交易日期在铁路、飞机、酒店、餐饮、市内交通中的企业定义；
7. 消费城市对交通票要求出发城市、到达城市、购票城市还是费用发生城市；
8. 目标租户允许使用的集成方式：已授权官方接口、用户可见的本地辅助操作或仅收据邮件；
9. 上传接口或页面能否返回并稳定读取报销单ID、费用ID和附件关联状态；
10. 页面字段是否有稳定的可访问性标签、选项 ID 或其他可验证标识；
11. 用户最终提交前，Concur 是否还会触发条件校验或新增必填字段。

这些确认结果应回写企业配置档案和本文件的字段映射矩阵，再开始正式的 Concur 草稿上传端到端验证。
