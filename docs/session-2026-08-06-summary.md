### 关键修复（本次会话）

#### 1. 多行明细税额求和（样本 04, 05, 27, 31, 36, 37, 38, 41, 43, 46, 54）

**问题诊断**：
- 初始实现：`find_in_column_sum` 将明细行和合计行全部求和
- 实测结果：所有样本税额翻倍（如 79.61 → 159.22 = 79.61 × 2）
- 通过率回归：从 77.3% 下降至 63.6%（-13.7%）

**解决方案**：
```rust
// 两层过滤
// 1. 直接文本匹配
if text.contains("合计") || text.contains("合 计") {
    continue;
}

// 2. 碎片化版式：同行有"合"或"计"单字
let same_line_boxes: Vec<_> = boxes
    .iter()
    .filter(|b| (b.center_y() - current.center_y()).abs() <= SAME_LINE_TOLERANCE)
    .collect();

let has_total_marker = same_line_boxes
    .iter()
    .any(|b| b.text.contains("合") || b.text.contains("计"));

if has_total_marker {
    continue;
}
```

**验证结果**：
- 10 个受影响样本全部修复
- 通过率恢复至 86.4%
- 净增 +4 样本（相比初始 77.3%）

**提交**：dbcbe49

#### 2. 购销方名称同框提取（样本 27, 31）

**问题诊断**：
- `find_buyer_seller_names` 只支持标签框和值框分离
- 样本 27 买方信息："名称：赛比亚医疗诊断器械（上海）有限公司"（同框）
- 函数查找右侧框失败，输出"无候选"

**解决方案**：
```rust
// 在邻框搜索前，先检查同框内值
if let Some(rest) = label_box.text.split("名称：").nth(1) {
    let candidate = rest.trim();
    if !candidate.is_empty() {
        return Some((candidate.to_string(), label_box.confidence));
    }
}
// 同框提取失败，降级到邻框搜索
```

**验证结果**：
- 样本 27, 31 buyer_name 成功提取
- PDF-VAT 通过率从 85.2% 提升至 92.6%
- 总通过率达到 90.9%

## 技术亮点

### 1. 系统性问题诊断

**多行求和回归案例**：
- 发现通过率异常下降 13.7%
- 识别所有受影响样本均为 2× 翻倍模式
- 通过文本框坐标分析定位根因（合计行未过滤）
- 实现双层过滤逻辑（完整标签 + 碎片化单字）

### 2. 渐进式优化策略

**版式适配层次**：
```
同框提取（最简单）
  ↓ 失败
邻框提取（标准版式）
  ↓ 失败
列求和（多行明细）
  ↓ 失败
列单值（表格降级）
```

每个层次独立实现，互不干扰，失败后自动降级。

### 3. 空间推理算法

**关键参数调优**：
- `SAME_LINE_TOLERANCE = 15.0` px：同行判定容差
- `x_tolerance = 20.0` px：列对齐容差
- `right - 5.0` px：右邻判定容忍轻微重叠
- `width > 80.0` px：跳过合并表头

所有阈值均经过真实样本验证，覆盖多种开票平台版式。
